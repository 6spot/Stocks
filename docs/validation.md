# 原型与端到端验收

本篇集中维护可验证场景与原型范围。数据与执行契约以相应[数据设计](data.md)、[任务执行](execution.md)和[研究设计](research.md)为准；返回 [架构总览](architecture.md)。

## 原型验证目标与边界

原型应完整覆盖“关注范围内的真实来源 → 持续采集和轻量分类 → S3/数据库情报沉淀 → 独立定时/手动综合研究 → 保存证据和报告 → Web 查看”的端到端路径。纯采集任务可以长期独立运行，无需每篇资料生成分析；定时研究也可以在采集源暂时不可用时使用已有数据并说明覆盖不足。

验证重点：已配置 RSS/财经媒体/API 全量收录各自配置范围内的新内容，所有实际获取渠道统一入库并处理；原始证据可追溯、V0 pgvector 检索、分类与按需 Fact、Document/Fact 统一取材去重、Repository First、YAML 定时报告、失败恢复和 ARM + Docker 部署。**不做采集前 `should_ingest` 判断，不建设 PostgreSQL 全文检索、证券主数据或证券级自动 Fan-out。**

### 研究分析与展示验收场景

- **无论是否抽取，原文始终保留**：已成功采集的两篇文章在分类时分别返回 `should_extract=true/false`，两篇均保留原始内容、来源和时间且能被后续研究检索；只有前者触发 LLM 抽取。重新分类或抽取失败也不得删除原文。
- **RSS 是发现入口，不是归档结果**：财经 RSS 频道里的新文章（包括不涉及当前 Watchlist 的内容）均尝试获取全文并保存 Document；不能只存地址、标题或摘要便认为完成。正文无法获取时保留已取得内容并标记不完整、支持重试。
- **同次轻量判断与模型可替换**：正常成功路径的一次 Decision Model 判断返回类别、标签和 `should_extract`，可切换模型配置但业务 Schema 不变；已完成资料不因切换配置而自动重新分类或抽取。长文只读取本次分类预算内的片段，其余片段仍保留；模型失败保留原文与待处理状态，不视为“不值得抽取”。

- **来源成功不等于数据完整**：采集频率只由关联 Task 的 `trigger` 定义，Source 的更新预期不作为第二套调度。RSS 请求成功但本期无更新显示为正常空结果；Connector 超时显示错误，月度指标未到发布日期不能按每天无数据报故障；已抓取但解析/分类/索引未完成显示相应积压。Overview 和 Evidence Package 均能够反映差异。
- **宏观指标和政策时间**：上月 CPI 本月发布，观测期、来源发布时间与采集时间分别记录；数值修订保留对应来源版本。政策草案与正式公告各自保留原文与日期，不将草案当成已经生效的政策。
- **数值准确性**：不同来源的收入值不一致时先核对财期、币种和披露口径；冲突各自保留，不平均覆盖。必要计算要有可复查的实际输入和单位，不要求独立金融质量平台。
- **独立来源与资料偏差**：仅有 SEC 一手披露时可以保存和使用，不强制第二来源确认或人工复核后才生成报告；两家转载同一原文不算独立。热门公司的新闻数多不得自动提高研究确定性，资料稀缺不能当作基本面差的事实。
- **反证与未知原因**：重要判断考虑相反解释；股价波动原因不明时记录“原因未确认”，不能编造归因比例。


- **同一研究 Agent**：市场、行业与个股 Task 分别提供不同 Scope/Objective 和 Evidence Package，运行同一个 Research Agent 结构化输出契约；不得为三类报告硬编码不同的引擎。
- **有变化也有不确定性**：政策公布确认但影响程度不明时，Researcher 可以生成关键政策事实和附带条件的风险推断；不允许把“可能影响”写成确定的经营损失。
- **没有显著变化**：如果本次没有足以改变主要判断的新证据，可生成如实说明的正常报告，不强制凑结论；资料不足时说明覆盖缺口。
- **证据交互**：点击报告引用可以查看原始 Document/Fact、原文位置或数值、来源时间和版本；多份报告可以复用同一资料，不依赖独立 Verifier 或 Finding 关系表。
- **缺失数据与生成故障**：输入有无法扫描的候选或来源故障时报告明确显示覆盖不完整；报告失败保留上次成功报告及其可读证据，不污染 Repository。

- **Document 更新时间**：分别保存文章首次发布时间、上游最后更新时间及 Stocks 采集时间。缺失的上游更新时间留空。仅来源更新时间改变、内容不变时不得虚增正文版本；同一 URL 的实际正文更新须保留新旧快照。
- **只按来源信号更新旧文章**：正常轮询 RSS/API 可以发现新条目及明确的更新提示；首次抓取新文章正文后，不创建周期性历史链接回访任务。RSS/API 更新信号出现时才复查已有文章的正文，内容未变不创建新版本，实际内容改变则保留新旧快照。研究授权的按需复查独立于例行采集，并将有价值的新资料重新入库。

- **不同渠道统一处理**：配置 RSS、新闻媒体和 API 持续收录配置范围内资料，不经过逐条相关性审批。外部搜索按研究目标选择实际读取的结果；所有获取入口将内容转换为相同输入契约、使用相同落库格式及 Document/S3、标签、按需 Fact、Embedding/pgvector 流程。RSS 不增加专属业务字段、表或后处理分支；完整性、来源和时间均使用通用字段。
- **V0 直接支持 pgvector**：入库的适用文章产生 Document Chunk Embedding，pgvector 语义检索能召回相关行业/政策背景，结合时间和来源过滤；Fact 可做结构化查询，无需 `tsvector` 全文索引或单独全文搜索系统。Embedding 失败不删除文章，状态可见并可重试；不得把失败当作没有相关资料。
- **原件与检索派生数据分工**：原始 HTML/JSON/PDF 等按内容版本在 S3 留存，PostgreSQL 保存元数据、Chunk、向量及必要 Fact，不再额外保存整篇清洗全文。HTML 正文与表格在后台解析，原数值、单位、脚注和来源关联保留；所有渠道共用相同流程。
- **检索不重跑解析**：一万或十万篇资料已建立索引后，查询只生成查询向量、检索索引并读取命中片段或 Fact，不遍历 S3、不重新解析全部原文。未完成解析/索引的文档显示实际状态并可重试；查询不会将处理失败伪装成无相关资料。

### 综合研究与采集验收场景

- **两条检索路径统一去重**：一份 CPI 官方公告 Document 与从中抽取的 Fact 均命中研究范围时，只作为一个相互关联的事实证据组进入模型；Document 仍可贡献没有被抽取的其他内容，原始记录都不删除。
- **API 响应与文章同源存储**：采集到一份含多项指标的原始 API JSON，保存一条原始响应 Document 并解析多条 Fact，各 Fact 都能追溯到该 Document 的字段路径；不对每条数值造一份原文，也不要求再调用分类模型。纯数值响应不适用文本索引时标为跳过，Fact 仍可查询，不误报为索引积压。
- **多源重复与冲突分离**：两份确定转载同一原文的新闻不重复计算独立证据；多个来源对同一统计期指标给出相同口径一致值可合并呈现但保留引用，口径不一致或数值冲突的原始记录必须同时保留，绝不静默平均。
- **分类/索引错误不丢资料**：成功收录的 Document 分类错误、没有 Fact 或 Embedding 失败时原文仍保存；类别错误不能让向量召回完全失效，索引积压或失败可观察、可重试。研究裁剪本次输入不等于删除原始资料。
- **重复运行幂等**：同一来源同一原文/响应重复采集及同一 Document 重试抽取，不制造重复 Document/Fact；原始内容变化或上游数据修订时保留新旧版本供研究追溯。
- **已完成抽取直接复用**：同一内容版本已成功抽取 Fact 后，重复采集、其他研究任务引用或切换模型均不自动再次抽取；失败重试、Owner 显式重新处理或新的内容版本才进入相应处理。


- **Repository First 的已有数据复用**：此前从 CPI 官方公告抽取并留存的数值、时间和原文证据已满足本次市场报告需要时，直接读取 Repository，不额外调用 CPI API；新闻、政策、财务、行情等资料同理。
- **缺口才补证并持续沉淀**：研究发现所需指标缺失、不够新或证据冲突时，经授权查询外部来源；有复用价值的新原文或结构化响应必须保存到 Repository 后供本次引用和后续任务复用。外部服务失败时仍可引用已有资料，但明确标识缺口与时效性，不臆造最新数据。
- **运行中补证可参与本次报告**：08:00 启动研究，08:03 通过授权工具取得昨天发布的公告，统一入库并完成本次所需解析后可用于本次分析；运行中取得的新发布或更新资料也可使用，并明确真实时间与版本。`as_of` 表示参考时间，不设置严格历史回放的取材限制，也不以发布时间晚于 `as_of` 拒绝本次补证；本次实际引用保存后可复查。

- **统一取材引擎与研究范围**：市场、行业和个股 Task 仅调整 Scope、Objective、预算和策略，均通过 `repository.select_evidence` 取材；Task 顶层定义的 Scope 固定为 `run.scope`，取材、游标与报告共用该范围，步骤不另设一份 Scope。直接资料和相关背景可使用不同查询条件，不把所有标签机械地当作必须同时命中的条件。
- **直接提及与背景关联**：研究 NVDA 可纳入未提及 NVDA 的半导体出口政策作为行业/宏观背景，但不能将其错误标注为原文明确提及 NVDA。
- **历史背景不是新增事件**：今日新分类的旧公告进入新增候选，而三个月前的财报可以作为背景引用；二者均保留原始时间与版本。
- **转载、分歧和证据独立性**：同一官方公告的多条确认转载不占多个主要证据席位，但不同机构独立提出的相反观点保留；无法确认是转载时不能仅凭内容相似强制合并。
- **容量边界与继续扫描**：500 条实际候选超出输入预算时，取材按维度裁剪并记录总发现/已筛选/选入数；如果检索只扫描了部分候选，标明 `retrieval_truncated` 与 `unexamined_count`，无法确定剩余数量时留空说明未知。在 Task/Run 保存原窗口、查询和分页进度，后续先继续该窗口，再打开后续窗口。可生成说明缺口的报告，但不能推进游标跳过未扫描区间；所有资料仍可被后续研究复用。
- **失败与可复现**：分类积压、来源断更和取材超时可定位；研究失败时可复用相同取材输入重试，不污染 Document，也不在报告未成功保存时推进研究游标。


- **跨研究复用**：同一份此前采集的官方财报能够同时被日报、行业周报和某只股票的专项研究引用。Document 只有来源、客观时间及处理状态，不存在属于哪个研究窗口或已被哪个 Run 消费的字段；每个 Run 的引用记录独立保存。
- **增量与背景分离**：日报增量窗口只包含昨天以来刚入库/更新的资料，但允许读取三个月前的财报验证新观点；旧财报属于 background，不被算作今天新发布的情报。
- **窗口无缺口**：周五日报成功后，周末发布的政策资料进入 Repository，周一日报必须能够纳入；某一次日报失败时不推进研究游标，下一次成功报告覆盖之前未处理的增量。
- **晚到资料**：一份上周五发布、周二才采集或完成分类的公告，仍可出现在周二研究的新增候选中；保留它真实的 `published_at`，不得把其发布时间错误更改为周二。
- **保存完成较晚不漏资料**：07:59 开始写入、08:01 才完成保存的资料未被 08:00 的例行扫描看到时，仍进入后续增量，不因写入开始时间早而遗漏。
- **研究范围变更**：同一任务从研究 NVDA 改为研究能源行业后，按新范围配置的初始起点或回看范围开始，不沿用旧范围的研究游标。

- **独立执行**：已配置新闻来源连续发布 100 篇新资讯，即使只有部分直接涉及当前研究主题，也按来源配置完成采集和可追溯入库；不因此创建 100 份报告。定时研究 Task 在需要时从 Repository 检索、筛选、去重，并生成一份综合报告。
- **故障隔离**：研究 Agent 不可用不阻塞采集、持久化及各自依赖仍可用的后台处理；分类、抽取和索引按自身依赖运行，共用 Provider 故障时相应步骤记录失败与积压。分类失败不阻塞已解析片段建立向量索引；某 RSS/API 暂停更新时，研究仍能使用已保存数据并说明时效性或覆盖缺口。
- **不做逐篇收录过滤**：配置财经 RSS 同时出现科技、能源和与当前自选股无关的新闻时都收录，配置 API 的数据不因当前研究任务不需要就丢弃；外部搜索不要求下载全部搜索结果，只保存实际取得的有用原文。正式分类发生在持久化之后，结果不决定删除。
- **情绪证据**：日报综合客观市场指标和不同发布者的资讯，标明“指标变化”和“模型归纳观点”的区别，不得以重复转载的新闻数量伪装市场整体情绪。
- **V0 任务简单**：两个 YAML Task 分别在设定时区的早晚时刻生成市场报告、NVDA 个股报告，使用相同的 Repository/Research Agent；采集、分类或抽取完成不会自动触发每篇文章的研究，也不要求自动按股票展开任务。
- **同一任务禁止重复运行**：同一个 Task 待执行或运行中再次收到手动、定时或重试请求时不新建 Run；两个请求同时到达也只创建一份运行记录。不同 Task 可以独立运行。
- **统一控制台管理异常**：采集、解析、分类、抽取、索引失败或取材积压均可从控制台定位原因并手动重试或继续；重试从失败或未完成步骤继续，复用已完成结果。Worker 中断后，Owner 可在确认旧执行已停止后结束异常 Run 再执行，不要求自动租约接管。
- **报告自动可读**：研究完成且输出通过结构及引用校验后，报告直接保存并可阅读；不要求逐份人工复核、批准发布或额外的人工验收操作。

### V0 一致性验收

- **公司/股票标签只代表有依据的直接提及**：一份 NVIDIA 公告可包含 `companies: [NVIDIA]`、`symbols: [NVDA]`；不确定的代码不猜测。宏观政策即使无公司/代码标签，仍可通过主题、行业、片段语义检索和来源/时间进入研究。
- **系统不建立证券主数据及自动证券任务拆分**：市场与个股报告使用 YAML 中的名称/代码标签即可完成。不建立公司—证券身份映射、历史代码表、逐条实体消歧或自动证券 Fan-out；这些不作为未来开发任务。
- **分类与采集故障不丢资料**：已入库 Document 即使分类失败或抽取失败，原文仍可查询；Worker 重试幂等且错误可定位。
- **报告的来源和数值可复查**：报告中的 Fact、时间和计算引用具体 Document 原文或 API 响应，不把不同来源相同表述自动当成多份独立证据。

### 后续增强（不作为 V0 交付门槛）

后续如有明确需要，可单独讨论事件驱动研究、复杂政策关联、Finding 历史关系及多轮核查；**不包含证券主数据系统或证券级 Fan-out**。当前详细研究扩展设计不是必需交付内容。

不纳入此产品基线：自动交易、行情高频撮合、复杂量化回测、多租户权限、分布式消息平台、复杂 DAG 可视化、多 Agent 自主协商和以模型为中心的自动路由优化。
