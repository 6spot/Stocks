## 系统主链路

~~~text
Source + Connector（按 Scope 持续采集）
    ↓
Intelligence Repository（原始文档、分类、实体、金融指标、政策版本）
    ↓ 查询
Task / Run → Evidence Selection（新增变化 + 历史证据）
    ↓
Research Agent → Findings → 可选独立 Verifier
    ↓
Report → Web Research（阅读、证据追溯、历史比较）
~~~

采集与研究是独立的 Task；资料长期共享，不为每份报告重新采集一套数据。**Repository First：研究优先查询已有情报和结构化数据；仅在资料缺失、不够新、存在冲突或需要核实时按需访问外部来源。新获得的有复用价值的数据仍走统一入库与来源追溯流程，供以后研究复用。** 上述为**逻辑链路**，不表示要拆分成多个服务或引入新调度引擎。

## 产品定位

Stocks 是面向单一 Owner、以美股为主要市场的个人投资情报与研究系统。系统按关注的股票、行业和宏观政策主题持续采集市场情绪、财经资讯、政策法规、公司披露及结构化金融数据，形成可检索、可追溯的情报积累；独立的研究任务再按设定周期或手动需要综合多来源资料，生成支持人工投资决策的研究报告。**产品交付的是阶段性综合研判，不是对每一篇新闻生成解读。**

核心目标：

- 尽量减少重复的人工搜集、整理、比对与查询工作。
- 支持多个独立投资策略和研究视角；不把投资风格绑定到底层架构。
- 来源、任务、提示词、模型、工具均可通过文件配置。
- 保存原始信息、证据、模型与提示词元数据，使研究结论可复核并能继续被上层分析复用。
- 先保持单人自用、轻量易部署，不建设交易平台、复杂工作流平台或自动下单能力。

## 系统原则

1. **Repository First，存量优先、按需补充**。研究先查已积累的原文、分类、可用结构化事实与历史资料；仅缺失、过期、冲突或需要核实的数据才按需访问外部来源。新得到的可复用信息返回统一 Repository，不将每次研究都默认变成实时 API 抓取。
2. **以 Task 为执行入口**。纯采集任务不需要 Agent，研究任务也不必经过固定的提取—判断—分析流水线。
3. **Source、Connector、Tool 不混用**。Source 表示数据发布者或上游，Connector 表示常规采集机制，Tool 是执行研究时的可调用能力。
4. **Agent 与模型解耦**。Agent = 角色定义 + 提示词 + 模型引用 + 授权工具。模型服务仅是可配置的 HTTP Endpoint。
5. **原文先存、处理后附加**。成功采集的资料保留原始内容；低成本决策模型进行分类、打标签和可选抽取决策，未抽取或抽取失败都不删除资料。报告是阅读视图，结构化结论与证据引用是附加的可追溯研究资产。
6. **原始资料与业务数据分离**。PostgreSQL + pgvector 管理业务与检索数据，独立 S3 兼容对象存储保存原始文档和快照。
7. **不把信誉当事实真值**。来源身份、信任等级、单条论断的可信性、核实状态各自建模。
8. **外部信息永远是数据，不是系统指令**。工具权限由配置和运行时授权决定，不能被外部正文改变。
9. **只做最小充分的调度与回退**。V0 使用 YAML 定义的定时/手动 Task、顺序步骤、必要的条件和有限重试，不引入证券级任务拆分、动态 DAG、模型评分路由或多 Agent 自主协商。
10. **原始数据与可复用事实分层**。文章、公告、API 响应均按原始来源记录和快照保存；分类与抽取决策属于 Document，按需整理的事实/数值作为可追溯 Fact 供研究使用，不为不同指标预建专属数据库。
11. **公司/股票是检索标签，不是主数据系统**。文档可记录原文明确提及的公司名称、股票代码，以及行业/主题标签；间接相关性不等于原文直接提及，歧义不强制确认。宏观、政策等不涉及具体股票的资料也能参与研究。
12. **持续采集与综合研究独立运行**。采集任务持续更新情报，低成本分类、标签和按需事实抽取不等于研究报告；研究默认按时间窗口定期或手动运行，高级事件触发留待后续。
13. **围绕 Research Scope 采集**。优先获取与自选股、关注行业、宏观及金融政策相关的资料，不将全市场无差别归档作为目标；同时避免仅按 Ticker 过滤而漏掉间接影响研究标的的市场事件。

## 概念与职责

| 概念 | 定义 | 负责 | 不负责 |
| --- | --- | --- | --- |
| Source | 信息发布主体或上游数据服务的一份配置 | 身份、采集范围、访问参数、信任级别 | 规定 AI 如何分析 |
| Connector | 通用采集实现：RSS、HTTP API、Web | 请求、增量获取、格式解析的通用流程 | 判定利好、组织研究任务 |
| Source Mapper | 特定来源的字段映射及必要解析规则 | 转换上游格式为统一信息记录 | 变成独立底层 Connector 类型 |
| Intelligence Repository | 原始情报、结构化事实与证据的统一数据访问边界 | 持久化、去重、索引、查询、来源关联 | 自主决定投资策略 |
| Document / Fact | 原始文章或 API 响应 / 从原始资料提取或解析的可复用事实 | 原文长期保留、分类与事实检索、来源追溯 | 将模型抽取结果视为已核实事实 |
| Classification | 文档的类别、主题、行业、公司/股票代码等检索标签与抽取决策 | 低成本模型判断，便于研究取材 | 把潜在影响当作原文直接提及或已核实事实 |
| Task | 一份可独立执行的工作定义 | 触发、步骤、条件、输入、输出 | 假设必定使用 Agent |
| Agent | 可配置的智能处理角色 | 提取、判断、分析、复核、工具调用请求 | 管理外部模型服务的部署 |
| Model Provider | 某种模型 HTTP API 的接入配置 | 认证、协议转换、超时、响应与用量归一化 | 决定投资判断标准 |
| Tool | Agent 或 Task 获得授权后可调用的操作 | Repository 读接口、远程 MCP 工具等 | 绕过权限或直接改变系统提示词 |
| Strategy | 可选的任务研究视角 | 目标、偏好、研究提示词与关注维度 | 固定 Agent、工作流或模型 |
| Report | 根据已保存分析结果形成的阅读产物 | 展示结论、风险、证据与待验证项 | 替代结构化分析存储 |

例如 SEC 是 Source，读取其数据可使用 HTTP API Connector 与相应字段映射；RSS 是传输形式，不代表发布者信誉；远程搜索/网页提取 MCP 属于 Tool。

## 数据与执行的关系

**默认执行模式：持续采集 → 情报沉淀 → 周期性综合研究。** 采集与研究是两个独立的 Task，Repository 是共享数据基础；二者不应形成“每收一篇新闻就调用研究模型”的同步链路。

~~~text
采集任务（依 Source 更新周期独立调度）
  RSS / HTTP API / Web
    → Research Scope：按来源能力限定采集范围
    → 原始内容快照、标准化记录、去重
    → 低成本分类/公司与股票标签/抽取决策、可选 LLM 事实抽取
    → Intelligence Repository（持续积累）
                    |
                    | 读取指定研究范围、时间窗口和历史结论
                    v
研究任务（按日/周定时，或手动触发）
    → 统一检索 Document + Fact，合并关联并去重
    → 必要时按需外部补证，重要新数据统一入库
    → 跨来源对照、识别变化与冲突、证据验证
    → 结构化 Findings 与综合研究报告
~~~

- 采集任务先保存原文，后续按需分类、打标签并判断是否值得抽取，**不要求对每条记录进行投资研判**。公司/股票信息直接作为有依据的检索标签；不设置独立的证券身份解析流水线。
- 数据在数据库和独立 S3 对象存储中持续累积；同一 Document 或 Fact 可被多份报告引用。研究任务按公司名称/股票代码、行业、宏观主题、政策类别、时间及原文内容查询，统一对 Document 与 Fact 合并去重，而不是只阅读最新的一篇资料。
- **研究窗口用于识别本次新增或新变更的信息，不用于限制研究可参考的历史资料。** 增量窗口独立保存在 Task Run / 研究任务游标中；历史背景、旧财报、此前政策与历史 Findings 可按研究时点在窗口外读取并标明为背景。资料不记录“属于某次日报”“已被某 Task 消费”这类任务专属属性。
- 采集故障不阻塞研究读取现有资料；研究 Agent、模型额度或报告生成故障也不阻塞新数据继续采集。研究报告必须说明资料覆盖区间、数据更新状态和已知缺失，不能把暂时未采集到数据解释为没有市场变化。
- 报告从多个维度识别**一段时间发生的变化**，可与历史报告/结构化结论比较；既不只是新闻标题列表，也不是逐篇正文的改写。
- V0 每个 Task 自己配置研究范围与定时时间；市场、行业、单只股票报告复用一套取材与研究流程。关注股票列表可放在 YAML，不强制扩展成数据库关系模型。
- Agent 可以根据明确授权调用 Repository 只读工具或远程 MCP Tool 补证；新证据先按来源与时间边界统一登记，再允许报告引用。
- V0 不因每次采集、分类或抽取完成就触发深度研究；自动事件驱动研究是后续增强，不属于首版闭环。
- 模型文本和新闻观点本身不是已经核实的投资事实。报告中的关键事实、数值和结论分别引用 Document、结构化金融数据和核查记录。

## 技术与部署

| 部分 | 选型 |
| --- | --- |
| 后端 | Python 3.12、FastAPI、Pydantic 2 |
| 数据库 | PostgreSQL + pgvector；SQLAlchemy 2、psycopg 3、Alembic |
| 采集 | httpx、RSS 解析、HTML 提取；按需增加解析器 |
| S3 | 标准 S3 兼容 HTTP API |
| MCP | Python MCP SDK，远程 Streamable HTTP |
| AI | 配置驱动的 HTTP Provider/协议 Adapter |
| 调度 | 独立 Worker + PostgreSQL 任务记录/租约 |
| 前端 | React + TypeScript + Vite |
| UI | shadcn/ui + Base UI + Tailwind CSS |
| 表格/图表 | TanStack Table、Recharts |
| 部署 | Docker Compose、Nginx；API 与 Worker 共享后端代码，分进程运行 |

单台 ARM 服务器运行 API、Worker、PostgreSQL 等应用组件；原始文件由独立 S3 兼容存储提供，私有网络负责连通。静态前端由 Nginx 提供；Node 构建工具不需要常驻生产进程。数据库使用持久化卷，不挂载到 S3。服务凭据通过环境变量或密钥管理提供，不能写进 Git。

自用系统仍必须为 Web/API 入口提供认证和访问控制。部署配置不能把数据库、模型管理接口等暴露到公网。
