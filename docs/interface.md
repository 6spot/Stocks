# Web 界面与报告展示

本篇定义面向单一 Owner 的页面和报告交互，不重复定义 Analysis 或 Evidence 的存储契约；参见 [研究设计](research.md) 与 [架构总览](architecture.md)。

**阶段边界：** V0 只需一个简明的报告阅读与证据查看入口；可以先由 API 提供同等能力，Owner 能读取报告和其实际引用的原件即可。V1 提供受保护的 Overview、Intelligence、Tasks、Research 和基础 Runs 控制台。V2 丰富历史对比、覆盖/费用分析及异常操作。公网或跨设备开放 Web/API 前必须加入访问控制。

## Web 产品界面

V1 采用响应式单人研究工作台，不开发 UI 组件库，不制作图形化 Agent/Task 工作流编辑器。布局由 Stocks 自己定义，基础按钮、弹窗、输入与交互原语使用 shadcn/ui + Base UI，统一采用 Nova 风格。技术选型见[架构总览](architecture.md#技术与部署)，组件、图标、动画、面板和拖拽的实现规则见[前端组件规范](../.trellis/spec/frontend/component-guidelines.md)。

工作台保持统一的字号层级、间距、边框、圆角、颜色和交互反馈，报告正文以长文阅读和证据定位为先。桌面需要并排阅读列表、报告和证据时，可提供可调整宽度的面板；手机上转为单列、独立详情或抽屉，保证主要内容和操作可达。拖拽仅用于已有明确需求的排序或移动，并提供按钮或菜单形式的等价操作；动画用于说明状态与空间变化，遵循用户的减少动态效果偏好。

主要视图：

- Overview：情报数据展览页，回答「已积累哪些情报、是否新鲜、有什么需要处理」。顶部为无框存量数字条（文档 / Fact / 报告 / 来源，附本周新增与采集时间跨度），随后是最近 14 天每日新增文档与 Fact 的柱状图（缺失日期补 0）、按来源的文档/Fact/最近成功/新鲜度分布表、需要处理清单、最新报告（标题/生成时间/独立原件/缺口数）与最近入库（标题/来源/采集时间/处理状态）。`attention` 由确定性规则产生，仅包含来源采集失败、已配置预期新鲜度但已过期的来源、最近一次 Run 失败的任务、失败或超过 1 小时仍待处理的处理阶段、来源/任务配置读取失败；为空时前端只显示一行「无阻塞」。运行列表、模型用量与处理积压明细属于 Runs 页，概览只保留「查看运行与积压」入口。
- Intelligence：以 **pgvector 语义检索** 为默认文本搜索，结合来源、公司/股票、类别、主题、行业、地域和时间过滤查询 Document，并可查询结构化 Fact；不提供另一个全文检索引擎。无股票标签或分类错误的文档仍可通过语义检索发现；向量未索引时展示处理状态。
- Tasks：任务名称、类型、可选策略、上次执行、状态和手动触发。已待执行或运行中的任务显示现有 Run，不重复发起；服务端执行[同一任务运行规则](execution.md#同一任务运行与异常处理)。
- Research：按时间、研究任务和范围查看综合报告、关键数据、分析依据、历史报告和资料缺口；可直接查看 Document/Fact 原始证据，并显示本次研究的模型用量（Provider、模型、Token、耗时与供应商返回的费用）及对应 Run 的步骤与模型调用入口。
- Runs：任务执行步骤、模型调用、费用、错误与回退信息。模型调用显示实际 Provider、模型、耗时、Token 与供应商返回的费用；没有提供费用的调用显示未知并给出未提供费用的次数，不按 0 计算。同时可查看积压/失败文档的来源、采集时间、最近尝试、失败处理阶段和重试状态，提供手动重试、继续扫描或处理积压的操作入口。积压面板的 `stage` 与 `status` 是两个独立筛选：初始只按 `status=failed` 查看全部阶段的失败项，阶段未选择时不发送 `stage`；`failed` 只是状态值，不属于合法阶段。进程中断或 Run 未正常结束时，Owner 确认旧执行已停止后，可结束异常 Run 并重新执行。

来源、模型、Agent、策略、任务和工具均以 YAML/Markdown/.env 管理；Web 只提供必要的查看与触发能力，不重复开发配置编辑系统。

上述视图共同构成统一管理控制台，集中处理任务、采集和后处理的异常与积压。控制台操作复用已有 Task/Run 和 Document 状态，不另建恢复调度平台；具体执行规则由[执行设计](execution.md)维护。

Intelligence 的搜索结果展示已存片段、来源、时间及命中依据，可读取相邻片段查看上下文。Document 详情分别提供已解析片段、Fact、原件查看/下载及处理状态；“已采集”与“可语义检索”分别显示。解析或索引未完成时可从详情进入相应重试操作，搜索不会为了展示结果触发全库解析。

### Owner 会话与 API 边界

API 只服务单一 Owner，不建设用户库或角色系统。`/health` 与
`POST /api/session/login` 公开，其余 HTTP 路由在应用级统一验证服务端签发的
HttpOnly、SameSite=Strict 短期 Cookie；原件下载走同一检查，不能通过直链绕过。
登录成功后，变更请求还必须带与当前会话绑定的 `X-CSRF-Token`。会话过期、损坏或
签名不符时返回 `401`，不读取私有报告、原件或执行操作；连续失败登录受时间窗限制。

控制台读取 `/api/overview`、`/api/sources`、`/api/documents`、`/api/facts`、
`/api/tasks`、`/api/runs`、`/api/processing` 与报告详情。列表使用有界
`limit` 和稳定游标，时间序列以 `(timestamp, UUID)` 或对应稳定标识翻页；
Document Fact 和 Document 版本各自按创建标识或版本号推进，不无界读取整段历史。

恢复操作包括触发 Task、重试或续扫 Run、结束异常 Run，以及只排队不执行的 Document
阶段重试。触发已有活跃 Run 时返回该 Run 并标记 `created=false`。结束 Run 与释放仍有
所有权的 Document 阶段都要求显式确认旧执行已停止，避免两个进程同时写入。Runs 详情
只返回去敏后的步骤定位、模型调用信息和安全错误，不输出凭据、Provider 端点或响应正文。

### 统一 Research 阅读与证据交互

市场、行业、个股使用同一个报告阅读界面，章节依据研究目标及实际证据动态呈现，不强制空栏目或空图表。

| 报告字段（V0 起） | 用途 |
| --- | --- |
| `report_id`、`run_id`（可选 `analysis_id`） | 关联本次研究和运行 |
| `title`、`objective`、`scope` | 标题、研究目标、范围 |
| `as_of`、`generated_at`；V1 增加 `changes_window` | 研究参考时间、生成时间，以及 V1 起的例行增量窗口；时间语义见[执行设计](execution.md#研究增量窗口与共享资料引用) |
| `summary`、`sections[]` | 摘要、章节及可选表格/图表 |
| `evidence_refs[]`、`coverage` | 实际 Chunk 引用及其 Document 版本；V1 起还可引用 Fact，附已知缺失、过期与冲突 |
| `research_inputs`（V2-01） | 本次研究的最终输入台账：初始边界条目、补充采用的 Document 版本、Tool 身份与时间关系；晚于 `as_of` 发布或采集的资料在证据区明确标注 |
| `coverage.origin_groups[]`、`metric_comparisons[]`（V2-03） | 本次选中的独立原件、确认同源的合并组，以及同指标各来源并列取值及其口径/观测期差异；报告页据此说明独立来源数、列出冲突值，均不标为已核实 |
| `final_metric_comparisons[]`（V2-03） | 初始选择加本次 Run 实际采用补证 Fact 的最终同指标并列取值；`metric_comparisons[]` 仍只表示初始选择，两者都不平均、不覆盖、不标为已核实 |
| `comparison`（V2-04） | 与另一份成功报告的前后对照结果（`GET /api/reports/{id}/comparison?other_report_id=...`）：结论新增/消失/持续与不确定性变化、引用 Document 的版本与内容变化、同指标取值修订、覆盖缺口增减与晚到资料；两侧各自保留片段与原件入口。比较集合只取该报告 Analysis/Findings 实际保存的引用，不把未引用的入选或补证材料当成报告依据，Fact 取值来自冻结投影而非当前行 |
| `previous_report_ref?`（V2） | 可选历史报告引用 |

基本交互：

1. **阅读研究**：显示主要变化、结论、理由、风险、不确定性和相关数据；报告页显示本次研究的模型用量并可跳转到该 Run 的步骤与模型调用；成功生成的报告直接可读，无逐份人工审批步骤；失败 Run 不替换最后成功报告。
2. **追溯证据**：点击引用先显示该报告实际使用的片段（V1 起也可为 Fact），附来源与原文位置、时间、内容版本及单位，再按需打开对应原件；V0 仅在本机访问，V1 起跨设备访问时原件与 API 使用相同认证，不依赖原网站仍然在线。HTML 原件以安全的文本或下载方式提供，不执行其中脚本。
3. **查看历史（V2-04）**：报告页可选择另一份成功报告做前后对照，默认选中同一 Task 中最近的一份。对照按 `created_at` 由早到晚呈现，逐项列出结论的新增/消失/持续（含不确定性与引用变化）、引用 Document 的新增/消失/同一来源的新版本、同指标取值修订、覆盖缺口增减，以及晚于较早报告 `as_of` 发布或采集的资料；两侧引用的片段与原件都可分别打开。比较只读两份已保存报告的快照，不重新研究、不改写旧报告，失败 Run 的报告不能作为对照对象。无需专用 Finding 关系图、Verifier 状态或独立核查界面。

报告区域区分**资料条数**与**独立原件数**：确认转载同一原件的多份资料标为「同一原件（N 份）」并各保留打开/下载入口，没有声明原件的资料按未知显示（V2-03）。同指标冲突值、不同口径与不同观测期并列展示，不做平均、不标为已核实。

历史报告对照把差异说成**真实来源变化**：晚到资料按发布/采集时间标注在较早报告的 `as_of` 之后，同一指标的修订显示两侧原值，未扫描候选数量保持未知，Task 或 Scope 不同、`as_of` 未推进时直接给出警告。

**列表与详情：** 研究页是全宽报告列表（报告标题 / 任务 / 状态 / 生成时间），点击行进入独立详情页 `/research/{report_id}` 沉浸阅读；列表页无选中逻辑、不自动打开报告。详情页首屏为返回列表入口、标题+状态+生成时间一行、单一信任行（独立原件数与引用条数）及必要的单行内联警告，其后即正文；证据包、来源与指标、研究用量以懒挂载 Tabs 在正文下方提供。旧深链接 `/research?report=<id>` 以 replace 方式重定向到 `/research/<id>`，浏览器返回不会落在旧链接上。对照模式在详情页内经「对照其他报告」以 `?compare=<other_report_id>` 进入，切换对照对象在详情页之间跳转，退出对照留在当前报告详情页。

报告附近说明不可用来源、资料缺失、重要冲突或候选截断，不能把未核实推断标成事实。图表值只能从已存 Repository 数据得到。Web 桌面和移动端共享内容，只调整导航与证据详情的响应式布局；配置仍通过 YAML/Markdown/.env 完成。
