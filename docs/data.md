# 数据采集、分类与 Intelligence Repository

本篇定义可复用的情报数据资产、来源接入和检索契约。执行与研究逻辑见 [任务执行](execution.md)、[研究取材](research.md)；返回 [架构总览](architecture.md)。

## Source 与 Connector 设计

### 通用接入类型

- **RSS/Atom**：订阅拉取与发现新文章/来源更新信号；用标题、摘要和元数据初步过滤，符合范围时获取文章完整正文，不能把只保存 Feed 条目或订阅地址当作完成采集。若条目本身已包含完整正文，可直接使用。
- **HTTP API**：认证、请求参数、分页、时间游标、JSON/XML 响应和字段映射；可预先按来源参数限制范围，对实际返回的适用数据保留原始响应，并直接解析可复用 Fact。
- **Web / 外部搜索**：检索发现只是候选发现手段；从符合范围的结果中取得原始网页、公告或可用内容，再进入同一 Document/Fact 处理路径。能直接取得完整内容时可保存该原始返回，不把搜索摘要当作完整文章；动态网页按需支持，不强制浏览器。
- RSS、API、外部搜索、研究 Agent 授权 Tool 及其他来源**共享同一候选过滤、原始资料持久化、分类、按需 Fact 抽取和索引流程**。区别仅在发现和获取方式，不增加某种来源专属的情报表或研究检索通道。来源可以预配置或在补证时登记，必须保留真实发布者、原始 URL/上游标识和采集渠道。

统一采集契约：

~~~text
fetch(source_config, cursor, scope) -> FetchBatch

FetchBatch:
  items:            IngestCandidate[]
  next_cursor:      opaque | null
  fetched_at:       timestamp
  metadata:         object
~~~

**所有纳入范围的资料统一形成可追溯的 Document。** RSS 用于发现文章，但文章 Document 以取得的原始正文/文件为内容，不能只是 RSS URL、标题或摘要。PDF、公告、网页和 API JSON/XML 响应也使用同一入库路径；一个 API 响应可以对应一份 Document 和多条 Fact，不必为每个指标制造单独 Document。Feed 原始响应可作为采集批次的来源材料保留，但不替代文章原文。

Document 至少记录：Source、上游 ID/URL（如有）、标题或可读说明、`published_at`（来源首次发布）、`source_updated_at`（来源最后更新）、`collected_at`（Stocks 实际采集）、原始负载/快照引用、内容哈希及版本关联。来源未提供的发布时间/更新时间留空，不用采集时间伪造；API 原始响应的字段按需解析为 Fact，未知值或口径不能猜测。

每个 Source 独立配置启停、采集周期、范围、请求限制、凭据引用与失败重试。采集必须支持限速、超时、幂等和数据量上限。用户配置或外部文档中的 URL 均须在抓取前进行网络目标校验，避免 SSRF、私网探测以及不安全重定向。

### 统一采集与处理契约（所有入口共用）

~~~text
RSS / API / 搜索 / 授权 Tool / 其他来源
  → 根据 Research Scope 进行宽松候选过滤
  → 对入选候选获取完整原文/原始 API 响应
  → 保存 Document + S3 原始快照与来源、时间、正文完整性状态
  → Decision Model 对文本分类、标签与 should_extract
  → 需要时 LLM 抽取 Fact；结构化 API 直接用 Source Mapper 解析 Fact
  → 为可检索文本生成 Embedding 并存储 pgvector
  → Repository 使用向量、结构化过滤和 Fact 查询统一取材、去重
~~~

1. **先过滤，再深度获取**：利用 RSS 标题/摘要、API 可用字段、搜索结果摘要及 Source/Scope 上下文做轻量相关性判断。保留公司/股票、行业、宏观、政策的间接关联候选；不确定但可能相关的内容进入后续获取，不因简单关键词未匹配而排除。明显无关的发现候选可以直接跳过，不必为每条搜索命中或 RSS Feed 条目建立 Document；采集 Run 保留数量/失败统计。
2. **入选即获取完整内容**：适用文章优先取得完整网页正文/原始文件并保存；Feed 已提供完整文章可直接使用。API 返回已是完整原始负载时直接保存，后续程序解析其中的适用字段。如果访问受限、正文获取失败或原网站只有摘要，仍保存已经获得的相关内容，标记为部分内容和具体失败原因，不将摘要冒充完整原文；可以按来源采集重试规则补齐。
3. **统一持久化**：成功收录的原文、文件或 API 响应先保存为可追溯 Document 和 S3 快照，随后才进行分类、标签、事实抽取与向量索引。任何后续失败不得删除已取得的资料；分类或 `should_extract=false` 不能反过来作为删除原文的条件。
4. **按内容选择处理**：适合文本理解的资料由 Decision Model 进行类别/主题/行业/公司标签和 `should_extract` 决策；值得抽取时由 LLM 生成 0..N 条带来源的 Fact。结构化 API 数据由 Source Mapper 直接生成 Fact，不强制先调用文本分类模型。所有 Document 均可参与后续研究检索；文本 Embedding 失败时保留索引待处理/失败状态和重试能力。
5. **统一研究入口**：定时 Task、手动 Task 和研究补证取得的可复用资料，都经同一个 Repository 持久化路径。Research Agent 不允许把新搜到的有用正文作为一次性临时结果使用而不落库；补证完成后继续使用已保存的 Document/Fact 引用。

这里的过滤是**候选发现与收录决策**，不是正式分类。RSS、搜索只提供 URL/摘要时不能以这些发现信息代替已取得的文章原文；获取失败须透明记录。

### 来源与发布者

系统分别记录：

- source_id：系统采用的采集来源。
- publisher / original_publisher：实际发布主体，必要时记录待确认。
- original_url / canonical_url：直接引用地址和可追溯原始出处。
- external_id：上游原始标识（如果有）。
- `published_at`：来源首次发布时间；`source_updated_at`：来源明确给出的最后更新时间（未知为 null）；`collected_at`：Stocks 实际采集该快照的时间。三者不能互相代替；指标观测期单独记录。
- trust_tier_snapshot：采集时的信任等级快照。
- content_hash：原始对象的完整性校验。
- storage_ref：远程对象存储中的原文/快照引用。

多个渠道转载同一原报道，仍可保存多个原始 Document，但证据核实不能将它们统计为独立证据。

### Research Scope 与有界采集

Research Scope 定义“**值得采集和后续研究的内容范围**”，与 Source（从哪里获取）、Connector（如何获取）及 Strategy（如何研究）分离。Scope 可由 YAML Watchlist（公司名称、Ticker、必要时市场）、行业、宏观主题和金融/监管政策主题构成；不要求每篇资料都直接提到某个股票代码。Watchlist 不对应独立主数据服务。

| Scope 内容 | 示例 | 采集原则 |
| --- | --- | --- |
| 关注公司/股票 | YAML 中的公司名称、股票代码及可选市场 | API 支持这些参数时按其能力查询；研究范围只是配置和检索条件 |
| 关注行业 | 半导体、能源、银行业 | 采集产业链、竞争格局、供应链及影响该行业的政策 |
| 宏观与市场 | 利率、通胀、就业、流动性、波动率 | 采集可观察的指标、官方发布以及相关金融资讯 |
| 金融政策与法规 | 货币政策、监管、出口管制 | 不要求公告直接提及关注的公司或股票 |

**已有文章的更新策略：来源信号驱动（方案 A）。** Source/Connector 按配置周期正常获取 RSS/API 的**新增条目和更新提示**；新文章首次获取时按条件取得并保存原始正文。对已经保存的文章，只有 RSS/Atom 提供 `updated`、API 给出变更记录/版本/修改时间等明确更新信号，或 Feed 条目本身实际更新时，才重新访问其链接获取新版正文；**不定期遍历历史文章、不建立自动回访任务**。研究确有事实缺口或需要核实时，可在已授权的补证流程中按需重新获取，并将有用的新证据回写 Repository。

来源给出更新时间或变化信号只是“值得重新检查”的依据，**不是内容已经改变的证明**。取得新正文后以实际内容判断：相同内容不增加 Document 版本，实际变化则新增不可变快照并保留旧版；只有更新时间变化不复制原文。来源不提供更新信号时，不为检测“静默修改”而反复访问历史链接。来源有条件请求能力时可利用 ETag/Last-Modified 减少流量，但它们不是新的更新监控服务。

**范围过滤与后续分类必须分开：** 来源查询参数先限制发现范围，再利用标题/摘要、源字段或搜索摘要对候选执行**宽松的收录过滤**；符合范围的候选获取完整内容并入库，明显无关的候选可跳过，记录数量即可。若候选相关性难以确定，优先获取并保存，避免因只匹配 Ticker 而漏掉间接影响公司、行业和宏观研究的资料。**正式分类、标签、`should_extract` 在 Document 已持久化后执行**，分类失误、相关性后续判断变化或不抽取 Fact，都不能删除已收录资料。

Research Scope 在采集入口统一应用，不在每个 Connector 维护第二套投资偏好。Source 的查询能力、权限、频率限制独立生效。

#### 来源更新、采集状态与覆盖

**不建设独立 Source Monitor。** 采集使用现有 Source 配置、Task 调度、`source_cursors`、`collection_runs` 和文档后处理状态；Overview/Runs 通过查询这些记录展示健康情况。

- Source 可以配置 `schedule`（实际轮询节奏）与可选 `expected_freshness`（根据该来源实际披露节奏判断是否过期），二者**不相等**：每 15 分钟查询一次 RSS 不代表每 15 分钟必须有文章；月度经济指标不能按日更要求判故障。不了解发布节奏时不设置硬性过期告警。
- Collection Run 记录 `started_at`、`finished_at`、`status`、`fetched_count`、`filtered_count`、`ingested_count`、`error_count`、`last_error`；与 Source 游标一起能够计算最近成功采集时间、失败次数及覆盖范围。原始请求成功且返回零条是**正常空结果**，不是报错。
- 三类状态分别呈现：**采集是否成功**、**来源是否按已知节奏更新**、**已入库资料是否完成分类及必要的事实抽取**。来源长期不发布、Connector 故障与模型处理积压不能混为一谈；缺失数据在研究覆盖信息中说明。
- 游标只在需要持久化的结果及采集统计成功提交后推进；失败 Run 记录原因供 Worker 按原有策略重试。采集计数支持发现过滤过严等问题，不能因为采集任务成功就断言所有应有资料都已覆盖。

不引入新告警调度服务、健康评分模型、专门心跳表或完整的外部数据发布日历。V0 先有可查询的事实、错误与缺口；真实来源有明确披露规律时再配置针对性过期判断。

## Intelligence Repository 与存储

**Repository First 的数据边界：** 新闻、公告、政策法规中披露的 CPI、利率、就业、企业财务和市场数据，与 API 获取的数值同样是可复用资料。**V0 采用 Document（原始资料）+ Fact（整理后的事实）两类核心情报记录**：所有成功获取的原始正文或响应先作为 Document 与不可变快照保存；Decision Model 为适用的文本资料标注分类、标签和抽取决策；需要结构化使用时，LLM 从原文抽取 Fact，或 Source Mapper 直接从 API 响应解析 Fact。研究优先查询这两类已存数据，只有缺口、过期、冲突或需要核实时才外部补充并入库。此处分层不要求新服务或为每种金融指标建专用表。

### 存储分工

- PostgreSQL：Source、采集状态/游标、Document 元数据与分类 JSONB、可检索正文、Fact、Task/Run、报告与证据引用。公司名称、股票代码、行业及主题只是可检索标签；系统不维护证券身份主数据表。
- pgvector：**V0 默认且必须实现**的向量语义检索。适用 Document 正文/片段生成 Embedding 并入 PostgreSQL pgvector，配合标签、来源、时间等元数据过滤以及 Fact 结构化查询；**不实现 PostgreSQL 全文检索（tsvector/GIN 全文索引或独立全文搜索引擎）**。
- 远程 S3 兼容存储：HTML/XML/JSON 原始快照、PDF、研报及较大的原始文件。数据库只保留 Object Key、内容哈希、尺寸、类型等元数据。
- S3 通过标准 API 访问。可利用 Tailscale 私有网络连接独立存储服务器，但应用不绑定某个私网产品或存储厂商。

写入流程为：**宽松预过滤并选取候选 → 获取全文/原始响应 → S3 保存不可变快照 → 数据库事务内保存 Document 和幂等键、更新游标 → 后台分类/标签、按需 Fact 提取、向量索引**。失败可重试；需保存的原文未可靠持久化时不能推进游标。**成功收录的资料始终保留，分类、Fact 抽取及 Embedding 的失败不删除 Document。** RSS 只有摘要且暂时无法获取全文时保留实际可得的相关条目与链接，标记正文缺失和补取错误，绝不冒充全文。相同来源相同内容幂等；同 URL 正文实际改变则保留新旧版本，仅上游更新时间变化不自动新增正文版本。

### 核心数据与公司/股票标签

Stocks 围绕长期积累和研究分析保存资料；公司名称、股票代码只是检索字段，不为公司、证券、代码历史或逐条提及记录建立独立主数据表。

| 数据 | 主要职责 |
| --- | --- |
| `sources`、采集游标及运行记录 | 来源配置、增量采集、失败和覆盖情况 |
| `documents` | 原始文章/API 响应的来源、时间、内容版本、S3 快照；当前 `classification` JSONB、分类/抽取处理状态及公司/股票等检索标签 |
| `facts` | LLM 从原文抽取或 API 直接解析的事实、数值、时间口径和证据位置，每条关联来源 Document |
| Document Chunk / Embedding（V0 必须） | 为适用正文切片生成向量，使用 pgvector 进行语义召回和原文定位；Embedding 失败不丢 Document，索引状态可恢复 |
| Task/Run、Analysis/Report 记录 | 定时执行、实际取材快照、分析与报告、来源引用 |

**公司与股票的最小规则：**

- Decision Model 可以在分类结果中给出 `companies[]`（原文明确提及的公司名称）、`symbols[]`（能依据原文和上下文明确指代的股票代码），以及 `related_industries[]`、`topics[]`（主题/间接相关性）。全部随当前分类存于 Document，不额外建立实体解析 Worker、历史代码有效期表或关联表。
- 关注列表先由 YAML 配置公司名称、代码及必要时市场/交易所信息。市场、行业、单股 Task 按配置的名称、代码、标签、原文全文和时间范围查询；不必给股票预分配内部身份 ID。
- 不能确定股票代码代表哪家公司时，保留原文及能确认的公司名称；不猜测代码，也不阻塞资料入库或研究。**直接提及与推测可能受影响必须区分**：某政策与半导体行业相关，不等于原文提及 NVDA；该文仍可以行业/宏观背景身份参与 NVDA 研究。
- 同一来源内容未变保持幂等；正文内容变化形成新 Document 快照版本，即使 URL 相同也保留旧版。来源更新时间只是元数据，不能单凭它判断版本。重新分类只更新当前分类，不新建 Document 或分类历史。
- 不以标签决定已入库原文是否保留。分类不确定、缺少股票代码或无 Fact 时仍能依靠 pgvector 语义检索与来源/时间过滤被发现；Embedding 尚未完成或失败时保留资料及可查询的处理状态，不把索引失败解释成信息不存在。所有研究均遵循 Repository First，并在统一取材环节与 Fact 合并去重。

**长期产品边界：不建设证券主数据系统、历史股票代码身份映射或按证券自动 Fan-out 的任务系统。** 这不是 V0 暂缓事项，也不列入后续增强。代码歧义只需保留原始内容与不确定性；研究可依据上下文和证据作判断，不建立证券身份数据库。

### 自动分类、标签与关联边界

分类是直接保存在 Document 中的轻量情报属性，不是逐篇投资分析；也不要求文章必须提到具体股票。宏观、行业、政策资料即使没有公司名称或股票代码，仍可完成分类、Embedding、pgvector 语义检索，并被定时研究任务读取。

**统一分类结果由 Stocks 定义，与模型厂商无关：**

| 字段 | 语义与约束 |
| --- | --- |
| `document_id` | 分类结果属于当前 Document；不为不同模型的分类单独新增 Document 或分类历史行 |
| `category` | 单个主要类别，来自受控词表，例如 `macro`、`policy`、`industry`、`company`、`other` |
| `event_type` | 可选的事件类型，如 `monetary_policy`、`earnings`；不适用时为空 |
| `topics[]` | 可多选的主题标签，例如 `interest_rates`、`inflation`、`liquidity` |
| `companies[]`、`symbols[]` | 原文有依据地明确提及的公司名称、可确认的股票代码；不强制填写、不猜测歧义代码 |
| `related_industries[]` | 文章讨论或可能影响的行业分类标识，属于**主题相关性**，不表示直接提及某只股票 |
| `regions[]` | 所涉及的地域或市场；不明确时为空，不根据语言猜测 |
| `method`、`model_ref`、`taxonomy_version` | 当前分类方式、模型/规则和词表引用；模型切换只回写当前分类 JSONB，不改变稳定标签 ID 与 `should_extract` 语义 |
| `classified_at`、`reason_or_evidence_ref` | 分类发生时间及可追溯依据；不能把模型分类标记成已经核实的事实 |
| `should_extract` | 同一次低成本分类请求给出的布尔抽取决策；表示是否需要后续 LLM 结构化抽取，**不是保留/删除原文的开关** |

标签及类别使用可配置的受控词表，前端与 Task 使用稳定标签 ID 查询。**V0 将当前分类、标签、`should_extract`、模型信息及分类状态保存在 `documents` 的 JSONB/必要状态字段中，不新建 `document_classifications` 或分类历史表。** 更换模型后可重新判断并回写当前结果；报告需要复查时由 Task Run 保存实际采用的输入快照，不为分类历史设计多套有效记录。结构化 API 响应不必强制走文本分类模型，直接由 Source Mapper 解析可用数据。

**自动分类流程与失败边界：**

1. Document 原文可靠入库后，Worker 先使用已知元数据/规则，必要时**一次调用配置的低成本 Decision Model** 完成类别、多个标签和 `should_extract` 判断。模型可以是 Jev、Cloudflare Clef/Clef-flash 或其他符合所需决策能力的模型，**不绑定某个厂商、模型或部署平台**。它选择预定义结果，不在这一阶段生成事实正文、数字或结论；通过[Agent 与模型配置](execution.md)的 Provider/Adapter 接入。
2. 分类与抽取决策必须符合固定 Schema 和受控词表；超出选项、模型故障或无效结构时按有限重试处理，保留原文及待处理/失败状态，不能默认为 `should_extract=false`。分类完成后，不论标签是否为空、类别是否为 `other`，文档仍在 Repository 中可查询。
3. `classification_status = pending / completed / failed` 及事实抽取状态直接记录在 Document 或相应处理任务中。重新分类回写当前结果，不另建历史表；实质变化可以进入增量研究。
4. 分类结果、状态和完成时间作为当前 Document 的处理信息可靠写入。Worker 只处理已保存的资料，按原有任务/重试机制处理失败与积压；分类变化的提交时间可供研究增量窗口查询。V0 不为分类完成创建独立的研究触发事件。
5. `should_extract=true` 才按需调用生成式 LLM 抽取 Fact；`false` 不触发抽取，但原文及标签始终可被研究检索。抽取结果作为独立 Fact 关联到来源 Document 和证据位置，失败可重试且不覆写原始资料。结构化 API 响应由程序直接解析 Fact，不强制进行 Decision Model 判断。
6. 模型应区分原文明确提及的 `companies[]`、`symbols[]` 与可能受影响的 `related_industries[]`、`topics[]`。后者仅供研究检索，不得自动生成某只股票被原文直接提及的标签；不能消除的名称/代码歧义留空或保留原始文字，不制造确定性关联。

**示例：**

~~~yaml
document_classification:
  category: macro
  event_type: monetary_policy
  topics: [interest_rates, liquidity]
  related_industries: [banking, real_estate]
  regions: [US]
  companies: []
  symbols: []
  should_extract: true
~~~

`should_extract` 只决定是否进入 LLM 事实抽取，不决定原文保留或研究资格。示例没有直接提及公司/股票，但可供宏观或行业研究使用；行业可能受影响是研究候选，不是确定的股票涨跌判断。

#### 市场情绪的数据含义

市场情绪是综合研究的一个输入维度，而不是一条新闻的“乐观/悲观”标签或模型自报的全市场分数。

- **可观察指标**：波动率、成交量、资金流及公开调查等可获得的数据可作为 Fact 保存数值、单位、观察时点和来源。指标解释交给研究，不将某个指标直接当作“市场情绪真值”。
- **信息叙事/观点**：媒体、研究机构、企业及政策发布的信息可按主题和可选的情绪倾向归类，保留原始出处与发布时间。模型给出的倾向属于来源文本的分类结果，不能自动代表整体投资者观点。
- **阶段性研判**：报告可以综合指标变化和多来源信息，得出带有证据、时间范围及不确定性的市场氛围判断；数据样本偏差、转载和观点分歧需要明确说明，不将新闻条数简单当作市场情绪统计。

可配置的分类模型只负责必要标签及相关性判断；“市场情绪如何变化、对哪些研究范围有意义”由定期研究任务在多源上下文中形成，而非每篇文档单独生成研究结论。

### Fact：结构化事实与数值（V0）

`facts` 保存值得重复查询和比较的内容：LLM 从公告/文章中按需抽取的事实，以及从 API 原始响应直接解析的数值。**所有 Fact 都引用来源 `document_id`**，证据可定位到文本段落、PDF 页码或 JSON 字段路径；API 一次返回多个指标时，可以用一份原始响应 Document 对应多条 Fact。不产生结构化信息的 Document 依旧可检索。Fact 不是替代原文的“真值表”，模型抽取的内容先视为带来源的陈述。

| 字段 | 最小语义 |
| --- | --- |
| `id`、`document_id`、`evidence_ref` | Fact 标识、来源原文/响应及准确证据位置 |
| `fact_type`、`subject_name?`、`symbol?`、`metric_id?` | 事实类型、明确提及的公司名称或代码、指标名称/标识（能确定时填写），不要求公司主数据外键 |
| `statement?`、`value?`、`unit?` | 文字事实或数值及单位；不存在则留空，不能虚构 |
| `period_start/end?`、`available_at?` | 指标所属时间/期间以及来源公开可获知时间，不等于入库时间 |
| `attributes`（JSONB） | 不同事实类型所需的可选扩展属性，例如政策生效日期、财务口径、OHLCV 数值 |
| `origin_method` | `llm_extraction` 或 `source_mapping`，区分模型提取与直接字段解析 |

通用字段用于按类型、主体、时间和指标检索；扩展属性不要求每种事实固定列或专属表。关系可简化为 `documents (1) → (0..N) facts`。原文更新产生新的 Document 版本，来自新版的数据以新的来源引用保存；源数据修订不覆盖旧研究实际使用的数值引用。同一文档重复处理应按来源版本及事实标识幂等，不因重试制造重复事实。

#### 数值与时间语义

行情、财报、CPI、利率、就业等均可从原始公告抽取或 API 响应解析为 Fact。系统不提供实时行情读取、金融时间序列或证券行情服务，也不为这些来源设置专属金融主数据表。实际取得的指标仍保留统计周期、单位、披露时间及来源说明，供研究判断是否可比。例如上月 CPI 本月才发布：观测期属于上月，发布和采集时间分别记录；修订数值保留来源与版本。

研究按 `as_of` 使用当时已经公开并被系统获取的资料；未知字段保持未知。报告引用具体 Fact 及其来源 Document/版本；同一 Fact 不因为查询路径不同而被当作两份独立证据。

#### 研究所需的数值准确性

这些是事实整理与研究引用的基本约束，**不是额外的金融数据质量平台、证券身份系统或实时行情计算服务**：

- API 响应和公告中的原始数值先完整保存；明确能解析的数值才作为 Fact 保存，未知单位或口径不猜测。
- 比较或引用数值时，要注意统计期间、单位/币种和必要口径。不同来源的冲突保留原值及证据，不用平均数掩盖。
- 研究需要同比、估值等计算时，使用确定性程序与可追溯输入，不让 LLM 凭空心算；没有必要预建所有金融公式或行情修订体系。
- 历史报告保存当时实际引用的数据和原文版本，之后资料更新不能静默改写旧报告。

### 来源关联、去重与政策资料

**首版不建设 Event 知识图谱、`event_documents`、`document_relations` 或政策生命周期状态机。** 这些关系不是情报积累和定时分析的前置条件。

- 同一来源、同一内容重复抓取保持幂等；不同渠道转载的原始 Document 可以保留，但研究取材时只把确认同源的资料视为同一组证据，并保存各自引用。
- 仅标题、关键词或语义相似不表示同一来源；独立观点、数值冲突及不同版本不得强行合并。
- 政策草案、正式公告、修订或生效说明各自保存原文和时间，研究凭具体来源文本判断其含义与适用状态，不将草案等同正式生效政策。
- 来源去重和证据独立性在统一的 [Evidence Selection](research.md) 中处理，不需要另建事件关系库或核验服务。

### 检索

Repository **同时查询 Document 与 Fact**：Document 使用 V0 默认的 **pgvector 语义召回**，可叠加类别/标签、公司/股票名称、行业、来源、时间等元数据过滤；Fact 按主体、类型、指标、期间和数值口径进行结构化查询。两者统一形成 Evidence Package 并去重，**不另建全文检索系统**。

标签不是唯一召回手段：无 Fact、分类失败、标签错误或未直接提及股票的文档，仍可通过向量语义搜索与来源/时间等字段查询进入候选。Embedding 未完成时其原始 Document 仍可读取，取材记录索引积压/失败，不假装已完成全部相关召回。

**pgvector 是首版必备能力**：Document/Chunk 的 Embedding 记录模型标识和维度；查询使用兼容的向量模型与相应索引，不混合不同模型的向量距离结果。原始内容可读与向量可检索是两个状态，分类及抽取失败也不阻止向量索引任务。

**取材查询接口：** `repository.search_changes` 以 Task Run 增量窗口和 `as_of` 查询新增 Document、Fact 或重要修订；`repository.search` 不受增量窗口限制，读取适用历史证据。两者可同时返回 Document 与 Fact 候选及稳定来源引用、数据版本和查询条件；**在统一 Evidence Selection 内合并关联并去重**，而不是分别给研究模型喂两份重复结果，也不能修改全局 Document 状态。具体去重见[研究取材](research.md)。

## 来源可信度、证据与安全

可信信息分为三个独立维度：

1. **来源身份与默认可信度**：T1 官方原始记录、T2 可识别原始发布者、T3 二手媒体/机构、T4 未核实来源。这些是可配置初始类别，不是客观真伪概率。
2. **具体论断属性**：披露事实、已知数值、个人观点、预测、未经证实的传闻，分别标记。
3. **证据支持程度**：研究的事实、推断与未经证实信息要区分，重要判断引用支持或相反的资料并说明不确定性；不要求独立核查运行表或状态聚合系统。

可高度信任官方系统确实披露了一份文件，但不因此认定文件中的未来预测必然成立。低等级来源可以作为线索，不可仅因级别低就静默丢掉重要未核实事件。可信度、重要性、交易价值不能混成一个分数。

安全边界：

- 原文、RSS 正文、网页、搜索结果和 MCP 返回值均为不可信数据，不执行其包含的指令。
- Agent 的 system 指令、工具白名单、参数边界由可信 Task/Agent 配置控制；工具实际执行前由 Stocks 校验。
- 外部服务默认仅授予只读搜索和提取能力，不授予交易、任意数据库写入、Shell 或密钥读取能力。
- 对抓取内容进行类型/大小约束、URL 安全校验、限流与日志脱敏。
- 重要研究判断引用可查证的 Document/Fact 原始依据，否则标明证据不足。
- “找到多条报道”不代表“多个独立来源确认”；需要追踪最初发布者与转载关系。
