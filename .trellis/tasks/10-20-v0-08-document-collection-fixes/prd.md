## 范围与要求

- R1 [P1]：最近内容与版本读取一致。`backend/src/stocks/repository.py:164` 复用任意历史相同哈希，而 `repository.py:266` 按最大版本号读取最新内容；“正文 A → 获取失败的部分内容 → 恢复正文 A”会使版本读取和最近采集状态不一致。恢复后必须返回实际恢复的正文及其不可变元数据，保留历史版本与引用；连续重复取得同样字节或仅来源时间变化不虚增版本。
- R2 [P2]：失败重试不依赖时间字段。`backend/src/stocks/collection/service.py:290` 在发布时间和更新时间均未知时直接跳过部分内容。后续手动采集仍须重试全文；未知时间保持未知，完整且无更新信号的条目继续跳过。
- R3 [P2]：畸形文章 URL 按单项失败处理。`backend/src/stocks/collection/feed.py:122` 在安全校验前解析 URL，格式异常可能逃出 `CollectionError` 边界。畸形链接及文章重定向目标须产生稳定脱敏错误，同批合法条目继续处理，不放宽现有 HTTPS、地址与响应限制。
- R4 [P2]：保留正文的声明编码。`backend/src/stocks/collection/http.py:287` 删除 `Content-Type` 的参数，导致后续解析默认使用 UTF-8。采集须保留解码所需的声明，合法非 UTF-8 正文能严格解码、正确分块并回查原件；不得改写原始字节或用替换字符掩盖错误。
- R5：修正归档记录。V0-01 `prd.md:36` 仍称 planning/未实施，`implement.md:31` 收尾项未完成；V0-01/V0-02 `task.json` 的说明也残留规划或待归档描述。以实际提交和验收证据修正最终状态，追加本次缺陷及修复任务关联，保留原有验证记录及其历史边界，不伪造补验结果。

## 验收条件

- [ ] AC-1（R1）：真实 PostgreSQL 中覆盖 A → B → A、完整 → 部分 → 恢复同一完整正文；最近采集状态、Repository 读取和采集结果的 Document ID、原件与完整性一致，历史 Document/Chunk 引用可读且不被改写；重复取得和仅更新时间变化保持幂等。
- [ ] AC-2（R2）：无有效时间字段的条目首次全文失败后，再次手动采集实际请求正文并能恢复成功；完整且无更新信号时不重复请求。缺失或无时区时间不被伪造。
- [ ] AC-3（R3）：同一 Feed 含畸形 URL 与合法条目时，前者留下安全错误，后者正常入库；畸形文章重定向也不使其余条目中断。原有私网、非 HTTPS 和超限拒绝行为保持有效。
- [ ] AC-4（R4）：固定 HTTP 响应声明非 UTF-8 编码且包含非 ASCII 正文时，采集后的声明和原字节保留，现有解析流程产出准确文本与可回查定位；UTF-8 正常路径及无效编码失败路径保持有效。
- [ ] AC-5（R5）：归档说明与 completed 状态一致，可从原任务找到本修复任务；新验收记录逐项给出实际远程命令、退出码、结果及限制，不把历史通过记录当作本轮通过。
