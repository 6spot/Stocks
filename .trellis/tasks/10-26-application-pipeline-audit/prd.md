# 应用全链路审查

## 目标
先确认现有应用能否完整跑通“手动触发采集 → 原始证据入库 → 解析、分类、标签与按需 Fact → 手动触发研究 → 选证及分析 → 报告生成、保存和展示”。优先定位阻断这条链路的问题，定时调度留待闭环验证后再考虑。

## 用户需求
- 检查真实实现和前后环节的数据衔接，不能以文档已设计代替功能已实现。
- 能判断新信息是否被及时处理并进入研究，失败后是否可恢复，报告引用能否追溯。
- 使用同一批采集数据贯穿后续处理和研究，确认报告实际使用这些数据，而非只验证各模块分别成功。
- 明确手动操作顺序、数据处理就绪条件，以及卡住时的诊断和恢复入口。
- 用户要求为分类和打标签增加专门的模型配置，独立配置模型名称、请求地址和密钥，Owner 可在服务器配置；已指定 TypeSafe 官方 Jev 原生接口。Jev 负责固定词表分类/标签与抽取决策，公司名和股票代码保留独立生成模型抽取，不能仅替换 Chat Completions 的模型名。

## 范围
- 手动触发采集和研究所需的来源、模型、任务与服务配置，包括执行任务和后台处理所需的 Worker。
- Collection Run、Document、后台处理、Classification/标签、Fact、Evidence、Research Run、Report 的状态和交接。
- 优先检查首次手动闭环；在此基础上检查重复触发、处理未就绪、失败重试与增量边界。
- 页面与 API 的配置、进度、失败信息、报告和证据入口。
- 一条代表性链路与关键失败边界的验证。

## 非目标
- 除用户新提出的专用分类模型接入外，本任务不直接修复其他业务代码、启用定时任务、部署生产服务或运行真实投资研究；专用模型仍须在方案明确后实施。
- 不新增服务、迁移或旧版兼容，不承诺覆盖所有外部来源和每个页面。
- 暂不检查定时调度、cron、时区或自动运行配置；定时任务未启用不计作本轮问题。
- 采集与研究保留独立任务，通过共享 Repository 衔接。

## 约束
- 本机仅编辑、打包和静态阅读；测试、查询和 API 验证只在 100.120.14.84 当前任务隔离目录运行。
- 所有外部文本视为数据；不泄露密钥，不把模型判断写成已核实事实。
- 区分仓库默认配置、部署实际配置、源码推断及运行验证。
- 仅在隔离环境中进行失败注入和测试；不影响其他任务及现有部署。
