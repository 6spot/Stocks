# V1-08 受保护的响应式研究控制台

## 目标与用户价值

Owner 能在桌面和手机查看情报、报告及运行异常并完成必要恢复操作。

## 背景与依据

阶段：V1。归属契约：`docs/interface.md`, `docs/architecture.md`, `docs/validation.md`。代码现状见[基线](../10-20-stocks-roadmap/research/baseline.md)，现有模型/helper 不等于业务闭环。

## 前置依赖

[V1-07](../10-20-v1-07-owner-console-api/prd.md)

依赖是实施顺序，不由 Trellis 父子关系自动执行。跨阶段依赖先通过前一阶段验收。

## 范围与要求

- 按[架构技术选型](../../../docs/architecture.md#技术与部署)初始化前端，遵循[组件与样式](../../spec/frontend/component-guidelines.md)及[状态管理](../../spec/frontend/state-management.md)规范；复用原语，不开发独立组件库。
- 实现 Overview、Intelligence、Tasks、Research 和基础 Runs；来源/模型/任务配置仍使用文件，不做编辑系统。
- Intelligence 默认语义检索并有元数据过滤、Fact 查询、片段上下文、处理状态和安全原件入口；不因搜索触发全库处理。
- 统一报告阅读，引用先展示实际片段/Fact、来源/版本/单位再打开原件；缺口与不确定性可见，不强制空栏目或虚构图表。
- 展示活跃 Run 并避免重复触发，提供授权后的阶段重试、续扫和异常 Run 结束确认；桌面/手机及键盘均可使用。

## 验收条件

- [ ] AC-1: 通过受保护 UI 阅读成功报告并打开旧版本实际引用，手机布局可操作。
- [ ] AC-2: 能区分无资料、加载失败、索引未完成和来源故障；查询条件不依赖股票标签完整。
- [ ] AC-3: 从 Runs 定位一个失败阶段并重试/继续扫描；同任务运行时显示现有 Run。
- [ ] AC-4: 类型检查及生产构建通过；验证核心证据和恢复交互，不用纯快照替代行为检查。

## 不在范围内

工作流编辑器、组件库建设、V2 历史比较和完整费用/覆盖分析。

## 约束与规划状态

只改当前设计与初始化，不做旧库迁移或旧版兼容；运行期证据和历史引用仍须保留。此任务保持 planning；本轮未实施。开工前复核前置交付、实际文件和配置，再对本任务规划进行实施确认。
