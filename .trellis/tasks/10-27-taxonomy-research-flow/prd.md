# 标签词表与手动研究闭环

## 目标
让 Owner 可以配置分类候选及其含义，使抓取的数据被一致地分类、打标签，再由独立研究任务按公司/股票、行业和主题取材，形成有引用的综合总结。

## 用户需求与授权
用户要求完整流程：抓数据 → 分类打标签 → 最后总结；认为模型需要候选领域、关键词及相似词，并询问这些配置属于任务还是其他位置。用户明确授权创建新任务并在设计后直接实施，无需再次取得建任务或实施许可。

## 当前已知
- 系统已有采集 Task、后台处理与研究 Task；`config/taxonomy.yaml` 提供类别、事件、主题、行业、地域 ID 与部分说明。
- Jev 已按词表生成 choice/noul 问题；开放公司与代码由独立生成模型提取原文依据。
- 现有应用闭环审查及 Jev 接入属于前一任务 `10-26-application-pipeline-audit`，其已复现问题不自动并入本任务。

## 需求
- 分类标签候选可配置，并能表达名称、语义、同义词/相关关键词，避免仅有英文 ID 的空洞候选。
- 给模型的是候选语义提示，判断仍由模型完成；不能以关键词命中代替判断，也不能将行业背景变成某股票被原文提及。
- 全局分类独立于研究任务；新增任务可检索既有数据，不需要把全部任务关键词汇总后重新分类。
- 研究任务可以配置其关注的公司/代码、行业、主题及问题；优先复用现有 Scope/query 与 Repository，明确直接提及与行业背景的差别。
- 给出可操作的采集、处理就绪、研究和引用追溯流程，以及一份可编辑的股票研究配置示例。
- 所有验证只在 `100.120.14.84` 当前任务隔离目录，保留受控/真实模型/真实来源各自证据边界。

## 验收标准
- 标签描述与别名能经校验进入 Jev 与现有生成式分类提示，输出仍只保存规范 ID。
- 不同任务能复用同一文档标签；名称/同义词是候选语义，不是另一个查询或输出 ID。任务使用规范标签 ID 和自然语言查询，不建立证券主数据库，也不新增词表别名解析或全标签精确过滤器。
- 股票研究示例显示直接公司证据与相关行业/主题背景均可被研究取材；未直接提及股票时不生成该代码。
- 一条同批数据流程能追踪采集、标签、适用 Fact、研究输入、总结及引用；实际使用哪些外部模型/来源如实记录。
- 同步唯一归属文档、必要测试与操作说明；不默认全量测试。

## 非目标
不建设证券身份/历史代码数据库，不为每只股票展开任务，不做关键词规则分类器、自动投资判断、多 Agent 平台或采集研究强耦合编排。不部署生产服务，不改动真实凭据，不把前一任务的两处原有缺陷顺手并入修复。

## 技术调查结论
现有 Taxonomy 已有 ID/部分 description，但生成式分类未接收完整语义，分类指纹遗漏语义字段；Jev 已有候选入口。最小设计为全局 id/name/description/aliases、共享模型语义与完整指纹，以及显式公司/背景语义查询示例。现有 Scope 不是已实现的精确标签过滤器；不在本任务扩大 Repository 查询契约。见 design.md 与 research/research.md。
