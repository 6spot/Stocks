# V1-05 提交可见变化水位与可继续扫描

## 目标与用户价值

研究增量按已提交变化推进，晚提交、晚到和处理完成的资料均不会被跳过。

## 背景与依据

阶段：V1。归属契约：`docs/execution.md`, `docs/data.md`, `docs/research.md`, `docs/validation.md`。代码现状见[基线](../10-20-stocks-roadmap/research/baseline.md)，现有模型/helper 不等于业务闭环。

## 前置依赖

[V1-04](../10-20-v1-04-facts-api-mapping/prd.md)

依赖是实施顺序，不由 Trellis 父子关系自动执行。跨阶段依赖先通过前一阶段验收。

## 范围与要求

- Document 入库、内容版本及解析/分类/Fact/索引可研究变化形成可追溯记录，水位按事务提交可见顺序推进。
- 不直接把 collected_at、published_at 或普通自增序列当可靠提交水位；实现需证明终点之前没有未提交空洞。
- 每 Task + Scope 独立游标，Run 开始时固定 (start,end]；首次起点明确配置，Scope 改变重置。
- 分页保存原窗口、查询条件与位置；扫描触顶/中断可继续，不因已产报告就丢剩余候选。
- 只有分析/报告成功保存且对应窗口扫描完成才原子推进游标；失败、取消不推进，Document 无全局已消费状态。

## 验收条件

- [x] AC-1: 双事务复现 07:59 开始、08:01 提交而 08:00 扫描：该变化进入下一窗口。
- [x] AC-2: 晚到旧公告、迟完成分类/索引/Fact 均进入后续可研究窗口，保留真实来源时间。
- [x] AC-3: 分页续扫沿用原窗口；报告失败或扫描未完不推进，完成后结果与游标同事务提交。
- [x] AC-4: 两个 Task 研究同资料互不消耗，范围变更重新初始化，边界记录不丢不重。

## 不在范围内

历史时点知识回放、全局消费标记、独立扫描服务。

## 约束与规划状态

只改当前设计与初始化，不做旧库迁移或旧版兼容；运行期证据和历史引用仍须保留。本任务已实施并在测试服务器全新数据库上验证，结果与限制见 [acceptance.md](acceptance.md)。
