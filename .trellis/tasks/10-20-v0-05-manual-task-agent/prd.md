# V0-05 手动 Task Run 与可配置研究 Agent

## 目标与用户价值

用可信文件配置手动执行研究步骤，保存配置快照、执行结果与模型调用信息。

## 背景与依据

阶段：V0。归属契约：`docs/execution.md`, `docs/research.md`, `docs/validation.md`。代码现状见[基线](../10-20-stocks-roadmap/research/baseline.md)，现有模型/helper 不等于业务闭环。

## 前置依赖

无业务任务前置；可先行细化。

依赖是实施顺序，不由 Trellis 父子关系自动执行。跨阶段依赖先通过前一阶段验收。

## 范围与要求

- 定义最小 manual Task、Run、StepResult；steps 顺序执行，when 只允许已执行结构化结果条件，不执行自由 Python 表达式。
- 研究 scope 在 Task 顶层唯一定义并保存 run.scope；记录目标、策略（可选）、模型和 Prompt/配置快照。
- 扩展现有 chat client 为研究所需结构化输出与调用记录；配置驱动 primary/fallback、超时、有限重试及错误类别。
- 同一 Task 的触发原子返回既有待执行/运行 Run，失败有记录且不覆盖最后成功结果；V0 可由手动执行进程领取。
- Agent 输入把外部内容作为数据；V0 只用已保存 Repository 证据，不执行外部 Tool。

## 验收条件

- [ ] AC-1: 手动运行示例 Task 可以成功、失败和跳过步骤，保留结构化 StepResult 和不可变运行配置。
- [ ] AC-2: 同任务重复触发返回同一活跃 Run，结束后可重新执行。
- [ ] AC-3: 429/超时等按配置有限回退，401/配置或能力错误不盲目回退，调用记录不暴露凭据。

## 不在范围内

定时调度、可靠增量水位、Decision 专有协议、MCP、动态模型路由。

## 约束与规划状态

只改当前设计与初始化，不做旧库迁移或旧版兼容；运行期证据和历史引用仍须保留。此任务保持 planning；本轮未实施。开工前复核前置交付、实际文件和配置，再对本任务规划进行实施确认。
