# V0-03 正文解析与可定位的持久 Chunk

## 目标与用户价值

将已保存原件转为能追溯原文位置的研究片段，不改写原始证据。

## 背景与依据

阶段：V0。归属契约：`docs/data.md`, `docs/research.md`, `docs/validation.md`。代码现状见[基线](../../../10-20-stocks-roadmap/research/baseline.md)，现有模型/helper 不等于业务闭环。

## 前置依赖

以下任务均已完成并归档：

- [V0-01 原件持久化与 Document 不可变版本](../10-20-v0-01-raw-document-versions/prd.md)
- [V0-02 真实来源采集](../10-20-v0-02-real-source-collection/prd.md)

依赖是实施顺序，不由 Trellis 父子关系自动执行。V0-03 只读取已提交的 Document
版本和 S3 原件；采集结果尚不存在的 Document 不属于本任务输入。

## 范围与要求

- 优先支持 V0 实际来源用到的 HTML/文本；按 MIME 选择解析器，不按采集渠道另建模型。
- 保存 Chunk 顺序、Document 版本与可核对原文定位；保留数字、单位、表格关系和限定条件，不用模型总结代替解析。
- 分块长度与重叠可配置；数据库不另存完整清洗正文。
- 处理在入库后显式执行，记录解析状态、错误和处理器版本；不适用/不支持格式明确记录，不伪装解析成功。
- 同版本已完成结果复用；显式重处理保留被历史报告引用的片段，不能原位破坏引用。
- V0 手动 CLI 可按 Document ID 或最新有界数量触发处理，默认输出计数和脱敏错误，不输出正文或凭据；显式 `--include-text` 仅供人工核对本批次正文与定位。
- 解析结果按不可变批次保存；最新尝试状态与当前成功批次分别记录。重处理失败只形成失败记录，不替换当前成功片段。
- Chunk 必须保留可用于复核的原文位置、Document 版本和批次关联；HTML 保留标题、段落、列表、表格行及顺序，文本保留字符范围。

## 验收条件

- [x] AC-1: 从保存的 HTML/文本原件生成片段，能按定位找到原文，数字及单位不丢失。
- [x] AC-2: 畸形或不支持内容保留原件和可读处理状态，不写成空正文成功。
- [x] AC-3: 重复处理幂等；指定文档重处理不会删除或改写已被引用的片段。
- [ ] AC-4: 用 V0-02 已保存的真实 SEC HTML 执行一次解析验收，核对 Document/批次/Chunk 关联、定位和内容样例；若外部环境不可用，明确记录未验收。

## 不在范围内

PDF/JSON/XML 解析、OCR、Embedding、检索、Fact 抽取、独立清洗服务和持久后台调度。

## 约束与规划状态

只改当前设计与初始化，不做旧库迁移或旧版兼容；运行期证据和历史引用仍须保留。
用户已授权按路线图继续实施；实现、真实来源验收和脱敏记录见
[验收记录](acceptance.md)。
