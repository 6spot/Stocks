# F-01：保留 Fact 重处理前的历史证据身份

## 问题与目标

同一 Document 的 facts 显式重处理会先物理删除已有 Fact，再创建新 UUID。即使抽取内容相同，旧报告保存的 Fact ID 也会失效，Fact 详情和历史比较可能丢失原值。目标是恢复同版本/同位置幂等与历史证据可复查的既有契约。

来源：[审查 F-01](../10-20-stocks-roadmap/research/implementation-design-review.md)。父任务：[修复计划](../10-22-implementation-design-fixes/prd.md)。优先级 P1，无前置任务；F-04 依赖本项。

## 范围与约束

- 文本模型抽取与 Source Mapper 两条 facts 路径都应遵守相同保留语义。
- 已保存 Fact 的 ID、来源、值、单位及期间不得因同一 Document 重处理被删除或静默改写。
- 同身份事实重复处理保持幂等；新发现的不同来源位置可以新增事实；源内容修订仍产生新 Document 版本。
- 不建立通用抽取纠错/事实版本平台，不新增历史迁移或旧版兼容。

## 验收条件

- [ ] AC-1：报告引用 Fact F 后，对同一 Document 显式重处理并得到相同事实，F 的 ID 和内容不变，事实不倍增，原 Fact 详情仍可读取。
- [ ] AC-2：文本抽取及 Source Mapper 都通过 AC-1；某次重处理未再产出 F，也不能删除已经保存的历史证据。
- [ ] AC-3：重处理在同一事实身份上给出不同候选值时不静默覆写旧值；新 Document 版本的数据仍保存为独立来源事实。
- [ ] AC-4：新位置事实可新增，正常重试仍幂等；阶段失败/所有权失效不留下部分 Fact、错误变更水位或已完成状态。
- [ ] AC-5：保存报告的原引用及事实值在重处理前后可读取并保持一致；F-04 的更精确比较口径留给后续任务。
