# 修复 MP-01：API 与 Worker 自定义配置一致性

## 目标与事实

修复既有审查记录的 MP-01：API 与 Worker 的自定义配置路径传递不一致，可能使 Owner 新增的来源、任务或模型未被实际执行。问题定位以[既有审查](../10-26-application-pipeline-audit/audit.md)及当前入口实现为准，先复现再确定最小修复边界。

## 需求

API 触发的 Run、Worker 执行以及相应手动入口应使用一致的显式配置。默认配置行为应可正常运行。检查 sources/tasks/models 及关联工具、词表配置在既有设置中的传递范围，不引入平行配置机制，不无故改动无关入口。

## 验收标准

- [x] 远程隔离环境以有明显差别的自定义配置复现问题，记录实际加载路径及非敏感配置身份。
- [x] 手动通过 API 触发并由 Worker 执行的 Run 使用预期来源、任务和模型配置，运行记录可核对。
- [x] 相关 CLI/部署入口传递一致；默认配置和缺失/非法配置的已有边界不受破坏。
- [x] 最小相关回归检查通过，执行契约及必要启动说明同步。

证据与限制见 [远程验证与交付](verification.md)。实现/验证完成，用户已授权归档、提交并推送。

## 前置与非目标

可独立优先推进；无需等待真实来源选型。新增真实来源最终验收依赖本任务。不做业务调度、全局配置平台或其他研究缺陷修复。

## 执行边界

需求草案已复核；用户在本轮明确授权开始实现。设计、执行计划及上下文已补齐，进入实施与远程验证。所有应用测试、静态检查和真实调用仅在测试服务器 `100.120.14.84` 的任务隔离目录执行；本机仅编辑和任务管理。不做数据迁移或旧版兼容，不引入额外服务、多 Agent 平台或证券主数据库。凭据不入库、不入任务记录或日志。
