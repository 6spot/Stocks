## 根因

共享 `.agents/skills/trellis-brainstorm/SKILL.md` 同时写有：

- 初始 build / implement / fix / go ahead 请求不算实施批准。
- 每个非简单任务必须在初始请求后至少再回复一次。
- 即使没有待澄清问题，也必须停在最终规划总结。
- “Only a subsequent user message that explicitly approves the latest planning summary authorizes task.py start and implementation.”

共享 continue 和 Pi continue 又把 planning -> 1.4 写成无条件询问 start；workflow 的 planning breadcrumb 也要求 ask for review。主会话因而把“细化规划”当成撤销既有执行授权，丢失了原指令中的后续动作。

此前模型组与子进程反馈修复没有处理该授权问题。规划材料齐备、review 和 task.py start 仍然必要，但不等于必须让用户重复同一条执行授权。

## 修正规则

归属 `.trellis/workflow.md`，同步共享 brainstorm / start / continue 技能和 Pi start / continue prompts：

1. 先查当前指令、会话决定和既有任务。明确执行某任务，或唯一可确定的下一任务，是对该范围的执行授权。
2. 仍补齐和审阅必要规划；没有新用户决策时，同一回合可 start 并派发，不要求规划总结后的新批准消息。
3. 创建 / 规划授权本身不等于执行授权。用户只要求规划时，完成后仍停止。
4. 新范围、验收、UX、风险或未授权外部动作，才需要询问对应的缺失决定。实现细节补齐不自动触发重新批准。
5. 提交、归档、日志和压缩不清空明确的后续执行指令。“下一任务”仅覆盖唯一确定的一项，不扩展成无限连续开发。
6. 明确要求提交 / 推送时，展示范围并执行已授权动作；不再机械要求回复一次“行”。未授权推送时仍不推送。

没有新建审批字段、权限状态机、调度器或任务。没有改业务任务的状态 / 代码，没有执行会话历史里的业务指令，没有自动提交或推送本轮后续文档修正。

## 阅读复核场景

- “只规划 V1-02” -> 完成规划后停止，不能自动实施。
- “执行现有 V1-02”且无未决产品决定 -> 补齐 / 审阅规划，start，派发 Implement，不重复确认。
- “提交并推送，然后开始下一个任务”，下一项唯一为 V1-02 -> 当前任务收尾后直接按既有授权进入 V1-02；不再要求“开始”。
- 规划发现未获授权的范围扩张 / 新风险 -> 只询问该决定。
- 用户只批准下一任务 -> 不继续 V1-03 或其他后续任务。
- 用户只说提交 -> 不自动推送。
