# 分类与实体依据可见性

## 目标与事实

使 Owner 能在现有 Web 文档详情检查文章被如何归类、是否明确提到公司及股票代码，以及处理失败发生在哪里。后端已有分类/实体依据与处理状态，现有前端展示不足；先复用现有接口和重处理能力，不建立第二套标注流程。

## 需求

按实际返回数据展示标签语义、公司/代码、实体原文依据、分类/实体处理状态、词表及模型身份中已有且可解释的信息。区分 Jev 标签判断与生成模型实体抽取，不把未抽出实体解释为文章不相关。允许利用已有显式操作重处理，并清楚显示等待、失败与成功；不新增自动覆盖历史证据的操作。

## 验收标准

- [x] 文档详情可检查标签、明确实体及其依据，缺失/未处理/失败状态有正确表达。
  新增 `ClassificationCard`：展示类别/事件/主题/行业/地域标签、公司与代码实体、逐条
  `entity_evidence` 原文引用表、模型分类理由、输入截断标记、词表版本与两次模型调用身份。
  无结果时按处理状态区分「尚未分类 / 等待后台处理 / 失败（含错误）」。
  真实页面核对：SEC 加密骗局公告显示 4 个公司实体+原文引用；FRED CPI 文档显示
  「无（未从原文抽出公司名）」；CNBC Oracle 文章显示「分类输入已截断（6000 字符）」。
- [x] 只有公司名无股票代码的材料不展示推断代码；行业背景不被展示成已提及公司。
  无代码时不渲染任何推断代码，仅显示固定说明「原文未明确代码；不从公司名或行业推断」
  （真实案例：SEC 公告 4 家公司实体 symbols 为空）；背景标签组固定说明
  「背景相关性标签，不表示文中提及公司或代码」。
- [x] 词表/模型身份不冒充投资结论，历史失败保留先前成功结果的语义可理解。
  卡片固定注明「实体与标签是模型判断，不是已核实的投资事实」；按角色分列显示
  「标签判断 jev-1.14.0 成功；实体抽取 deepseek-v4.1-flash 成功」；
  classify 失败且已有旧结果时显示「最新一次分类尝试失败……下方展示的是此前已保存的
  分类结果，未被失败尝试覆盖」并保持旧结果可读（真实失败+旧结果并列核对通过）。
- [x] 现有重处理入口可用且结果状态清楚；若能力不足，先在设计中明确最小补充。
  设计确认后端数据与 `POST /api/processing/retry` 已够，无后端改动；文档详情处理状态表
  对 failed 阶段新增受控重试按钮（复用 Owner 会话+CSRF+`OWNER_CONFIRMATION_REQUIRED`
  确认流）。真实闭环验证：将一篇 CNBC 文档 classify 置为 failed → 详情页点击重试 →
  「阶段已重新排队」→ Worker 重新执行 → 状态回到 completed（attempts=1）。
- [x] API/Web 改动范围内的必要远程检查和真实页面核对完成。
  远程隔离目录：`npm run typecheck` ✓、`npm run test` 76/76（连续两轮）✓、
  `npm run build` ✓；新增 `classification-card.test.tsx` 6 个用例覆盖有实体/无实体/
  无结果/失败保留旧结果/等待/非投资事实说明。真实页面用 headless Chromium 在部署环境
  核对（登录→Intelligence→文档详情），API curl 断言 classification 字段与
  processing_stages 真实返回。

## 前置与非目标
