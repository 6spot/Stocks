# V2-03 来源独立性与冲突证据呈现

## 目标与用户价值

研究区分同源转载、独立观点和口径冲突，避免报道数量制造虚假确定性。

## 背景与依据

阶段：V2。归属契约：`docs/research.md`, `docs/data.md`, `docs/validation.md`。代码现状见[基线](../10-20-stocks-roadmap/research/baseline.md)，现有模型/helper 不等于业务闭环。

## 前置依赖

[V1-09](../10-20-v1-09-arm-deployment-acceptance/prd.md)

依赖是实施顺序，不由 Trellis 父子关系自动执行。跨阶段依赖先通过前一阶段验收。

## 范围与要求

- 在 V1 基本去重基础上，依据明确出处关联确认同源资料，保留各原件与源头引用。
- 仅标题/语义相似不能认定同源；独立反面观点、不确定来源关系及数据冲突并列保存。
- 数值比较先核对期间、单位、币种与口径，冲突不平均、不静默覆盖；必要计算使用确定性程序和实际输入。
- 报告与证据详情区分来源等级、论断性质和证据支持，说明样本偏差，不以新闻条数自动提高确定性。

## 验收条件

- [x] AC-1: 已确认转载合成一组但可打开所有原件；相似主题的独立观点不误合并。
      采集时把来源自己声明的原件（canonical 链接 / 文章绝对地址 / feed 绝对 http(s) id）记在
      Document 内容版本上，取材阶段只用这个声明合并：声明相同 → 同一个 `OriginGroup`，
      `document_count` 增加而每份 Document 仍保留自己的 Chunk、Fact、引用与原件入口；
      标题、摘要、向量相似与 feed `<source>` 都不参与合并。集成测试覆盖「确认转载合并为一个原件组、
      两份文档都可引用」与「标题相同但地址不同 → 两个独立原件组」。真实来源核对：Fed 与 SEC
      公开 RSS 各 20 条真实条目分别得到 20 个互不相同的结果原件键，没有被误合并。
- [x] AC-2: 同指标冲突值及不同口径在报告中可同时追溯，不能自动标为已核实。
      `metric_comparisons[]` 对同一 `(subject_name, symbol, metric_id)` 的多条 Fact 分别标记
      `value_conflict` / `basis_mismatch` / `period_mismatch`，逐个列出取值、单位、币种、观测期、
      可用时间、陈述与 Document；`render_report()` 确定性生成 `## Sources and Conflicts`，
      把各来源值并列写出并声明「不平均、不覆盖、不标为已核实」，不依赖模型复述。
      测试断言 2.4 与 3.1 同时存在、包内不出现平均值，且不同观测期只标记期间差异。
- [x] AC-3: 同源数量增多不会被描述成更多独立确认，重要反证和未知关系如实呈现。
      覆盖统计区分 `selected_count` / `evidence_group_count` / `origin_group_count`，
      `independent_source_count` 固定为 1；没有来源声明的资料记为 `single_document`
      并保留 `document:<id>` 键，报告明确写「独立原件数未知，不等于资料条数」。
      研究提示词要求按独立原件计数并把反证与未解决关系如实写出；报告段落由已保存数据生成。

## 不在范围内

事件关系库、来源真值评分、独立核查平台。

## 约束与规划状态

只改当前设计与初始化，不做旧库迁移或旧版兼容；运行期证据和历史引用仍须保留。Owner 已授权按 V2 任务列表逐个实施；本任务已实施并交付：`evidence_packages` 直接增加 `metric_comparisons` JSONB 列（改 `0001` 初始化定义、空库重建，不写增量迁移），已保存的 Document 原件、Chunk、Fact、旧 Evidence Package 与报告引用不被改写。

**待 Owner 验收（不阻塞后续任务）**：真实「多来源转载同一原文」的成对样例与真实来源给出的同一指标冲突值本轮没有取到（公开来源通常不声明 canonical、也很少给出相互矛盾的同一指标），真实采集端的同源合并与冲突取值呈现仍需用实际来源复核；事件关系库、来源真值评分与独立核查平台不在范围内。
