# Pi + Trellis + Magpie 多模型环境配置

## 目标

Magpie 管理路由组内的具体模型、Provider、认证和转发，Pi 运行主会话和 Subagent，Trellis 保留原生规划与执行流程。项目只指定角色对应路由组，用户自主决定何时规划、何时执行。

## 当前事实

- Pi 1.3.0、Trellis 0.6.17、Magpie 0.1.1306；已有 Trellis Pi 集成和 Magpie Provider，无需重新初始化。
- 用户已创建 OpenAi、Deepseek、Qwen 三个组，实际 ID 为 `openai`、`deepseek`、`qwen`；三个 `group/<id>` 条目已在 Pi 导出清单中找到，当前成员家族分别符合角色需求。
- 用户明确要求不直接指定具体模型，此要求取代早先的单模型候选选择方案。
- Check 原生拥有编辑和 shell 工具，职责包括直接修复问题。
- 运行验证仅允许在指定测试服务器执行；此前 SSH 认证失败，尚无运行验收结果。
