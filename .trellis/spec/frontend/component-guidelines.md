# 组件与样式规范

组件按清晰职责拆分；页面负责组合，通用组件负责可复用的交互或展示。Props 用 TypeScript 明确声明，避免通过宽泛对象、隐式全局状态或不透明的字符串约定传递数据。只有出现真实复用需求时才抽取共享组件，不预建独立组件库。

## UI 与视觉基线

基础按钮、输入、弹窗等交互统一复用 shadcn/ui + Base UI，采用 **Nova** 风格；新增组件从同一套配置生成，避免在不同页面混用不同风格或交互原语。首次初始化时将 Nova 风格与 Base UI 基础配置记录在实际的 `components.json` 中，并以所选版本的官方配置为准。

- 样式使用 Tailwind CSS；颜色、圆角、间距、字号和阴影通过统一设计变量表达。优先使用 `background`、`foreground`、`muted`、`border`、`primary`、`destructive` 等语义 token，避免为同一种状态在不同页面写不同色值。
- 通用控件的尺寸和状态通过组件 variant 管理；业务调用点不重复覆盖按钮、输入和弹窗的基础样式。
- 报告正文、数据表格和操作区各自保持一致的字号与密度；同列数值对齐，来源、时间、单位和不确定性可读。上涨、下跌、错误等状态同时提供文字或图标，不只依赖颜色。
- 焦点、禁用、加载和错误状态必须可辨认；图标按钮、Tooltip、Dialog 和 Drawer 仍须保证可访问名称及正确焦点行为。

## 图标：Lucide

统一从 `lucide-react` 按需导入图标，不混用其他图标库、emoji 或 Unicode 符号作为操作图标。品牌标识和原始资料中的图片按内容资源处理。

同类控件保持相同的图标尺寸、描边与文字间距，颜色默认继承 `currentColor`。装饰图标设为 `aria-hidden`；只有图标的按钮在按钮上设置可理解的 `aria-label`，Tooltip 不能代替可访问名称。

```tsx
import { ExternalLink } from "lucide-react";

<Button variant="ghost" size="icon" aria-label="打开原始证据">
  <ExternalLink aria-hidden="true" />
</Button>
```

## 动画：Motion

需要程序化动画、进入/退出或布局过渡时，统一使用 `motion`，React 组件从 `motion/react` 导入。简单的 hover、focus 和颜色反馈可用 Tailwind/CSS transition，不额外引入动画库。

- 动画服务于状态反馈、层级和空间关系；不为报告正文、长列表或频繁数据刷新批量添加入场动画，不延迟阅读或操作。
- 微交互默认使用 120–180ms，弹层和小范围布局过渡默认使用 180–240ms；同类交互复用相同参数，需要弹簧时集中定义配置。只动画必要属性，优先使用 `transform` 与 `opacity`，避免 `transition: all`。
- 使用 `useReducedMotion` 或 `MotionConfig` 响应系统减少动态效果偏好，移除非必要位移、缩放和弹簧，保留立即可见的状态反馈；CSS 动画也遵循 `prefers-reduced-motion`。
- 同一属性的动画只由一个机制控制；使用 shadcn/ui 自带的 CSS 过渡时，不再叠加 Motion 控制同一属性。退出动画期间仍须正确处理焦点、遮罩和不可交互状态。

## 可调整面板：react-resizable-panels

普通页面排版使用 CSS Grid/Flex；列表、报告与证据等需要拖动分隔条调整大小的区域，统一使用 `react-resizable-panels`。可通过 shadcn/ui 的本地 Resizable 封装复用该库，不自行实现指针拖动分隔条。

面板必须设置合理的默认尺寸、最小尺寸和可见的调整手柄，允许键盘调整并提供可理解的名称与焦点样式。手机宽度改为单列、详情页或抽屉，避免压缩成不可读的多列。尺寸持久化仅在需要记住用户偏好时启用；库自身管理的尺寸不再复制到 Zustand，高宽等实时拖动状态不触发全局刷新。

## 拖拽：dnd-kit

列表排序、条目移动等拖拽交互统一使用 dnd-kit；不以 `react-resizable-panels` 实现业务拖拽，也不另写 HTML 原生拖拽状态机。具体包和 API 在实现时按所选版本的官方文档确认，不混用不同版本的示例。

- 仅在明确需要排序或移动的功能中启用，配置稳定的业务 ID、独立拖拽手柄以及适合鼠标、触屏和键盘的输入方式，避免误触滚动、链接和文本选择。
- 提供键盘操作、可读的操作结果反馈，并保留按钮或菜单形式的等价操作；取消拖拽恢复原位置，不把取消或无目标放置视为成功。
- 拖拽中的坐标、命中目标和预览留在局部；确认放置后才更新业务顺序。需要服务端保存时显示提交结果，失败恢复或保留可重试状态，不把本地顺序当成服务端已保存。
- 拖拽预览和位移动画由 dnd-kit 控制时，Motion 不同时控制同一元素的 `transform`。

## 组件位置与证据展示

页面和组件的目录应跟随实际功能边界保持可查找；目录模式形成后在此记录真实文件路径和最小示例，不把假设的目录树写成既定规范。

对外部内容采用安全文本展示，避免未经审查的 HTML 注入。证据交互必须区分“实际引用片段或 Fact”和“打开原件”两个动作。界面先展示来源、Document 版本、位置、时间与单位，再提供原件查看或下载；HTML 原件不得直接注入页面执行脚本。空结果、加载失败、索引未完成、来源故障和无资料必须使用不同的可读状态。
