# 前端质量与验证

交互组件应可用键盘操作，控件有可理解的名称，焦点和错误提示可见；使用 UI 原语时仍要检查实际组合后的行为。涉及外部内容展示时检查转义与安全呈现。

前端同样遵循**只做必要测试，不默认全量测试**：围绕本次修改的组件行为、类型边界或布局风险选择最小检查。简单可逆改动或纯文档修改无需机械新增测试；相关检查通过后即可停止。有明确的跨页面或构建风险时再扩大范围，并说明原因。

构建、lint、类型检查和测试命令应以实际前端包配置为准；交付时准确列出执行过的命令，不把未运行的检查写成通过。

## 前端工程建立后

- 类型检查和实际生产构建是完成 V1 前端任务的必要检查，具体命令从 `frontend/package.json` 读取。
- 核心证据追溯、空/错/未完成状态和恢复操作需要至少一次行为测试或浏览器验收，不能用纯截图替代交互断言。
- 在桌面和手机宽度检查导航与证据详情；使用键盘完成主要阅读和恢复路径，并核对焦点、控件名称及错误提示。
- 若引入单元或浏览器测试框架，先在实际包配置和本规范中记录真实命令、环境与覆盖边界；不要预设尚未安装的 Vitest、Testing Library 或 Playwright。

涉及解析和证据阅读时，至少验证以下状态可被区分并恢复：

- `completeness = partial` 与完整内容分别显示，保留安全的获取错误类别。
- 最新解析批次失败但存在旧成功批次时，仍可读取当前 Chunk，同时显示最新失败。
- `unsupported`、尚未解析、处理中、空正文和普通网络错误不是同一种“无数据”。
- 报告 `as_of`、来源 `published_at`、`source_updated_at`、`collected_at` 和解析
  尝试时间各自显示，不能合并成一个更新时间。
- HTML 原件和 Chunk 内容按纯文本安全渲染或提供下载；不得直接注入执行。
