# 前端目录结构规范

当前仓库尚未建立 `frontend/`，没有可观察的 React 源码目录或构建配置。V1-08 创建前端工程后，以实际目录和真实文件为准记录本文件；在此之前不得为了填满规范而创建空目录或宣称某条目录规则已经落地。

## 已确认的边界

- 页面、功能组件、复用 UI 原语和 API 访问代码应由真实职责分隔，页面只组合功能，不把所有状态和请求堆在单个页面文件中。
- shadcn/ui 生成的本地原语与业务组件分开；业务代码不在调用点复制通用交互和样式。
- API 请求、运行时响应校验和时间转换集中在网络边界，组件不各自维护不一致的响应形状。
- 浏览器路由、认证、搜索筛选和证据读取应保持薄边界；Task、游标、处理状态和权限判断以服务端为准。
- TanStack Table 与 Recharts 只在实际页面使用；不为尚不存在的表格或图表创建共享封装。

## 落地时更新

V1-08 首次建立 `frontend/package.json` 后，把已验证的源码根目录、页面/组件/hook/API 客户端位置、测试位置及配置文件名补充到本文件，并同时更新 [前端规范索引](index.md) 中的真实命令。目录里确实出现第二条同类边界时再形成规则，不预建 `components/common`、`hooks/utils` 等空壳。
